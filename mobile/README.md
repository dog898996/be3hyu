# 호영이 Android 앱

0.4.7: 열린 Work 선택창을 놓치는 감지 조건과 입력창 외곽 안내를 초안으로 읽는 경로를 수정했다. **Work → 연결**에서 선택창 열기·확인·닫기를 처리하며, 백그라운드에서 멈춘 선택창 애니메이션도 정리한다. 실제 기기 성공 여부와 재현 검사 범위는 [배포 기록](../docs/release-v047.md)에서 구분한다.

0.4.2: 최종 코드 감사에서 장기 사용 누적 오류, 진행 중 작업 라우팅, 새 지시 처리, 첨부·알림·계정 편집·복구 경로를 수정했다. [설치·검증 기록](../docs/release-v042.md) · [지속가능성과 백업의 정확한 범위](../docs/final-code-audit-v042.md) · [모델·프로필 설정](../docs/routing-and-identity-v041.md).

휴대폰 앱이 ChatGPT 일반 Work 대화에 요청을 전달하고 원문·기억·계정·작업 파일은 폰에 보관한다. 사설 VM이나 상시 PC는 사용하지 않는다. 0.4.0의 [11개 화면](../docs/ui-redesign.md)을 확인할 수 있다. 설치 파일·다운로드 지문과 최신 검증 상태는 [배포 기록](../docs/release-v046.md)에 모아 둔다.

## 설치와 연결

1. 해당 버전의 APK를 설치하고 앱을 연다. 앱 회원가입은 없다.
2. **시작할 준비** 화면에서 지원되는 필수 기본·특수 권한을 모두 허용한다. Android 설정을 열었다는 것만으로 완료 처리하지 않으며, 필수 권한이 빠지면 대화·Work·설정 이동을 막는다. SMS·통화 기록의 설치 프로그램 조건과 실제 grant를 별도로 표시한다.
3. 사이드바의 **Work**에서 본인 ChatGPT에 로그인한다. 이 인증은 ChatGPT 구독 연결이다. 로그인 제공자가 임베디드 브라우저를 거부하면 해당 제공자가 지원하는 로그인 방법을 확인한다.
4. **연결**을 누른다. 페이지 로드 뒤에도 자동으로 확인하며, 지원되는 모바일 계정 메뉴를 한 번 열어 계정 표시를 확인하고 닫는다. 빈 새 대화에서는 Work를 선택하고 앱에 지정한 모델·강도·Fast를 자동 적용한다. 웹에서 모델을 다시 고르거나 선택창을 열어둘 필요가 없다. 필요한 선택창을 앱이 열고, 모델·강도·속도 확인 후 닫는다. 기본값은 6.1 Sol·Medium·Fast다. 감지되지 않으면 **⋯ → 연결 상세 / 연결 진단 복사**에서 확인한다. 미확인을 로그인 실패로 단정하거나 설정값을 실제 선택으로 간주하지 않는다.
5. **연결됨**이면 대화 탭에서 사용한다. 필요한 경우에만 **⋯ → 연결 동작 테스트**로 실제 도구를 확인한다. 이 테스트는 모델 사용량을 소모하며 일반 연결에는 필요하지 않다.
6. 사이드바의 **설정**에서 사용자 지침·모델·계속 맡길 목표를 정하고 자율 모드를 켠다. 새 설치의 AI 판단 기본 간격은5분, 로컬 폰 상태 확인은1분이다. 기존에 바꾼 간격은 유지하며 진행 중 작업과 중복 실행하지 않는다. 상시 알림의 중지 버튼으로 자율 호출을 끌 수 있다.

세션을 바꿀 때는 **⋯ → 새 Work 대화**를 누른다. 앱 소유 대화 삭제의 완료 표시를 확인한 뒤 새 대화를 연다. 자동 확인이 실패하면 웹에서 해당 대화를 직접 삭제한 뒤 **⋯ → 삭제 확인 복구**를 이용한다. 이 동작은 계정의 별도 저장 메모리를 지우지 않는다.

권한 화면에는 실행기의 전체 도구 목록이 표시되며 기능은 기본 허용이다. **알림·다운로드·실행 방식**에서 잠금 화면 답장 내용·시스템 제안 동작·Work 파일 내려받기와 실행 한도를 바꾼다. 턴·행동 개수의0은 앱 개수 제한 없음이다. 지원되는 설정은 대화에서도 변경한다. [실제 권한과 기능](../docs/permission-capability-matrix.md).

사이드로드 APK의 알림 접근·접근성 설정에는 Android 앱 정보의 **제한된 설정 허용**이 필요할 수 있다. 실제 grant는 재개·전송·도구 실행 때 다시 확인한다. root·기기 소유자·시스템 서명 권한은 일반 앱 설치로 제공되지 않는다. [권한별 기능과 제한](../docs/android-permissions.md).

### 갤럭시 설치 차단: 화면 문구를 먼저 확인

**‘악성 앱으로 의심’과 ‘이 제한은 끌 수 없습니다’가 함께 표시되면**, 아래의 일반 Auto Blocker 안내와 다른 차단이다. 출처를 알 수 없는 앱 설치를 허용해도 판정이 해제되지는 않는다. 삼성 담당자는 보이스피싱 방지를 위한 별도 설치 제한과 APK 검토 절차를 안내한다. 현재 배포본 0.4.3의 서명·APK 구조 검사에서는 오류가 발견되지 않았지만, 실제 차단된 파일과 기기의 판정 사유는 아직 확인되지 않았다. [분석 결과·검토 경로·확인되지 않은 범위](../docs/samsung-install-block-v043.md).

**‘자동 차단 기능으로 설치 차단’이 표시되는 경우:**

**출처를 알 수 없는 앱 설치**가 허용되어 있어도 삼성 **보안 위험 자동 차단(Auto Blocker)**이 켜져 있으면 외부 APK 설치를 별도로 막는다. 이 문구만으로 APK가 악성코드라는 판정은 아니다. 본인이 설치하려는 APK를 확인한 뒤 **설정 → 보안 및 개인정보 보호 → 보안 위험 자동 차단**을 잠시 끄고 설치한 다음 다시 켠다. Play Protect는 유지한다. 이미 출처 불명 설치를 허용한 설치 앱의 설정을 반복해서 바꿀 필요는 없다. [삼성 설치 차단 안내](https://www.samsung.com/us/support/troubleshoot/TSG10001914/)

아이콘이나 서명 변경으로 OS 설치 정책이 해제된다고 보장할 수 없다. 현재 0.4.3의 manifest 권한 선언은 48개다. 알림 접근·접근성 서비스도 유지하며 실제 Android 허용 상태를 별도로 확인한다. 설치 후 Android의 **제한된 설정 허용**과 지원되는 필수 특수권한을 부여한다. 이는 설치 후 권한 설정이며, ‘악성 앱으로 의심’ 설치 차단을 해제하는 설정은 아니다. [Android 제한된 설정 안내](https://support.google.com/android/answer/12623953?hl=en)

이미 debug APK를 설치했다면 release의 서명이 달라 바로 업데이트할 수 없다. 기존 앱의 파일 탭에서 외부 백업을 내보낸 뒤 debug 앱을 제거하고 release를 설치·복원한다. 설치가 차단되어 기존 앱이 없는 경우에는 백업·제거 단계가 필요 없다.

## 대화와 계정

대화 화면에서 사진·영상·일반 파일을 여러 개 첨부하고, 가벼운 근황에는 AI가 문장 대신 이모지로 반응할 수 있다. 반응도 대상 원문과 assistant 응답으로 저장해 기억·읽음·백업에 남긴다. 입력 중 표시는 실제 사용자 답변에만 사용한다. [UI·반응 저장 구조](../docs/ui-redesign.md).

**계정**에서 서비스·아이디·비밀번호의 최신 값과 수정 이력을 관리한다. 인증앱 비밀키·복구 코드·추가 인증 메모를 입력하고 고급 JSON 정보도 보존한다. TOTP는 입력 직전에 계산하고, 복구 코드는 반환 전에 사용 예약을 남긴다. 외부 보존 폴더 오류로 공개하지 않은 예약은 새 대화에서도 검증된 참조로 이어받는다. 이미 공개를 확정한 코드는 옛 백업으로 자동 재공개하지 않는다. SMS·이메일·알림·패스키 인증은 해당 절차의 실제 화면·권한·결과를 확인한다. 비밀번호 입력 접수만으로 로그인 성공을 보고하지 않는다. 이 개발 채팅에 보낸 계정이 설치된 앱으로 자동 복사되지는 않는다. [로그인·MFA 검증 범위](../docs/account-login-status.md).

계정 보관함 삭제는 전용 복사본과 수정 이력을 처리하며 계정을 알려준 일반 대화 원문은 남긴다. 일반 대화도 지우려면 기억의 원문 관리에서 삭제한다. 계정 원문·추가 인증 정보는 전체 기억 ZIP에, 삭제·제외·복구 코드 예약은 외부 정책 보존에도 포함한다.

## 기억과 파일

대화 원문, 출처가 있는 기억과 정정 이력은 내부 SQLite에 저장하고 큰 원문은 `filesDir/originals`, 작업 파일은 `filesDir/projects`에 보관한다. 첨부 원본은 해시를 붙인 불변 파일로 남긴다. 재생성 가능한 캐시와 구분하므로 일반 캐시 삭제로 지워지지 않는다. 앱 데이터 삭제·제거·폰 초기화 전에 **파일** 탭의 백업을 외부에 내보낸다. 백업에는 ChatGPT 로그인 쿠키와 브라우저 프로필을 넣지 않는다. [원문·첨부 보존](../docs/attachment-originals.md)

**기억** 탭에서 원문을 확인한 뒤 **AI 기억에서 제외** 또는 **원문·파생기록 삭제**를 선택할 수 있다. 제외는 원문을 남긴 채 이후 모델 조회를 막는다. 삭제는 관련 답변·기억 수정 이력·관리하는 로컬 복사본을 함께 정리하고 실제 완료·대기 범위를 표시한다. **0.3.1부터 새 ZIP 백업에는 이식 가능한 삭제·제외 정책도 포함**한다. 복원은 현재 정책과 백업 정책을 합쳐 적용하고 최신 정책을 오래된 기록으로 덮어쓰지 않는다. 제공자 서버나 이미 내보낸 백업 자체를 삭제했다고 표시하지 않는다. [제외·삭제 동작과 검증 범위](../docs/source-privacy-and-deletion.md)

**파일 → 보존 폴더 선택·다시 연결**에서 `Documents/호영` 같은 일반 폴더를 선택한다. 삭제·제외가 바뀌면 작은 정책 기록만 별도 IO 작업에서 자동 보존하고 실제 저장 파일의 hash를 다시 확인한다. 큰 대화·기억·첨부 ZIP은 **보존 폴더에 대화·기억·파일 백업 저장**으로 같은 폴더에 내보낸다. 전체 기억의 자동 주기 백업은 아직 아니다. 외부 보존이 대기 중이거나 접근 오류일 때 완료로 표시하지 않으며 완료 표시 전에 앱 데이터를 지우면 최신 정책이 외부에 남지 않을 수 있다.

재설치·데이터 삭제 뒤에는 Android 폴더 권한도 초기화되므로 **같은 보존 폴더를 먼저 다시 연결한 다음 ZIP을 복원**한다. 그러면 최신 외부 정책을 먼저 합쳐 옛 ZIP의 삭제된 기억 재등장을 차단한다. ZIP에 들어 있는 정책은 그 백업 시점까지의 정책이므로, 이후 삭제가 있었으면 최신 외부 기록이 필요하다. 0.3.0의 이전 ZIP 형식은 읽을 수 있지만 정책이 들어 있지 않으므로 외부 폴더 연결이 특히 중요하다. `Android/data`·`Android/obb`는 보존 위치로 거절한다. 앱 제거와 별개로 공유 폴더 자체를 지우거나 폰을 초기화하면 외부 백업도 없어질 수 있다. [재설치 보존 구조와 시험](../docs/reinstallation-memory-preservation.md)

사진·영상·음성·문서와 일반 파일은 Android 파일 선택기로 가져와 내부에 복사하고 대화에 첨부한다. 첨부 원본은 최대 64 MiB까지 그대로 보존한다. 브릿지가 실제 Work에 전달하는 예산은 한 파일 10 MiB, 총 20 MiB, 최대 8개다. 큰 사진은 원본을 남기고 예산에 맞는 별도 이미지 사본을 만들며 원본 해시·전송 해시·변환 여부를 모델과 기억에 구분해 전달한다. 영상·음성·문서 등의 바이너리는 자르거나 압축 변환하지 않고 정확한 바이트를 전달할 수 있을 때만 보낸다. Work 파일 입력이 해당 형식을 받지 않거나 업로드 준비 상태를 확인하지 못하면 파일을 빼거나 텍스트만 대신 보내지 않는다. 앱 파일 보관 기능은 서비스의 모든 형식·크기 지원을 뜻하지 않는다.

일반 작업 파일 보관은 한 파일 512 MiB까지다. 백업 압축본과 복원 전개 데이터는 각각 기본 64 GiB 한도로 스트리밍하며 설정에서 1~64 GiB로 바꿀 수 있다. 실제 저장 공간·외부 제공자 파일 제한은 별도이므로 진행 중 실패와 복원 반영 여부를 표시한다. 결과 파일은 앱 도구의 파일 쓰기 또는 허용한 HTTP/HTTPS Work 파일 다운로드를 통해 저장한다. 실제 쿠키·로그인·형식·완료 상태를 확인하며 blob 다운로드 등 지원되지 않는 경로는 직접 저장해 가져온다.

원문을 삭제하고 요약으로 대체하지 않는다. 전체 키워드 검색에 실제 공개 ONNX 모델의 폰 내부 512차원 의미 검색을 결합한다. 약 138MB 모델은 비종량 네트워크에서 체크섬을 확인해 받으며, 임베딩 계산용 외부 API 요금은 없다. native ANN 후보의 원래 F32 벡터를 재정렬하고 원문 해시·기간·현재 권한을 확인한다. 모델이나 색인이 준비되지 않았으면 기존 원문 검색을 유지하고 준비 범위를 표시한다.

출처별 검토 범위, 중요한 선호, 정정 revision, 기간, 별칭, 진행 중 목표를 따로 관리해 오래된 관련 원문을 다시 찾는다. 새 원문 검토와 사진 분석은 구분하며, 사진 원본 저장만으로 읽고 이해했다고 표시하지 않는다. 일반 대화에 미검토 원문을 한꺼번에 붙이지 않는다. 자동 판단에는 직렬화된 작은 검토 배치를 함께 넣어 긴 작업 때문에 기억 정리가 밀리지 않게 하고, 실제 유효한 검토 ACK만 진도로 기록한다. 별도 검토 요청도 유지한다. 검토 원문과 주변 대화의 실제 출처는 답변·작업 영수증·목표에 연결하며 제외·삭제·현재 권한을 전송과 결과 반영 시 다시 확인한다.

1~2년 설계의 검증은 합성 대량 자료·공개 검색 자료·기억 추출 probe로 나눠 공개한다. 365회 가상 세션의 저장·정정·조회 시나리오와 독립 모델의 선택된 문맥 독해도 각각 기록한다. 1년 20MB나 완전한 회상을 보장하지 않는다. 백만 합성 텍스트만으로도 DB와 WAL이 약 510MiB였으며 사진·벡터·원문 spool은 별도다. [연구·측정 범위](../docs/memory-research.md), [실제 모델 probe](../docs/model-memory-evaluation.md), [365회 시뮬레이션](../docs/longitudinal-memory-product-benchmark.md)

사용자가 업로드한 **세션과 기억처리** RFC v1.2 원문은 1,034줄 전체를 읽었다. SHA-256은 `4b778bdb7d71abc838bafcffa05bf83c2b105ad4e2837ce620cb32857ef21194`다. [항목별 구현·검증 대조](../docs/memory-rfc-integration-plan.md)와 [최신 5년 모의 기록 결과](../docs/five-year-memory-final-source-v7-results.md)에 구현 범위와 미검증 항목을 구분해 기록한다. 원문 검색, 실제 답변 채점, 앱 전송, 실제 폰·Work 실행 결과는 별도 증거로 확인한다.

## 실행과 복구

전송 전에 원문·요청 ID·첨부·실행 저널을 저장한다. 같은 입력의 접수·완료 이벤트와 폰 도구 실행 결과를 분리하고, 프로세스 중단·확인되지 않은 전송은 자동 반복하지 않는다. 명시적 재시도는 새 시도 ID를 사용하되 원 요청과 도구 영수증을 이어 받아 같은 부작용을 반복하지 않게 한다.

백업에서 되살린 미완료 요청은 확인 대기로 격리한다. 복원은 이미 실행한 일을 다시 실행했다는 뜻이 아니며 자율 모드는 사용자 확인 후 켠다. 작업이 진행 중이거나 결과가 미확인인 상태에서는 복원으로 실행 기록을 덮어쓰지 않는다.

사용 한도는 실제 서비스 안내로 판단하고 한도 소진을 앱 자체 메시지로 알린다. 유료 API·사설 VM·크레딧 자동 구매로 전환하지 않는다. 사용자의 재시도 선택은 실제 한도 회복의 증거로 표시하지 않는다.

사용량 절약은 기본으로 켜져 있다. 사용자 답변 속도 선택(기본 Fast)·기억 검토 Medium 이상을 유지하고, 정기 판단 기본은 Medium·Standard다. 명시적으로 Low를 선택한 경우에만 Light 판단 경로를 사용하며, 복잡한 경우 High로 승격한다. 일평균10%는 관측 목표이며 목표에 도달해도 대화·자율 판단·기억을 중단하지 않는다. 실제 Work 사용량 화면을 확인하기 전에는10% 달성으로 표시하지 않는다. [사용량 최적화](../docs/token-optimization.md).

새 사용자 입력은 즉시 저장하고 이전 전송 승인과 폰·앱 도구 제안이 그 입력보다 오래됐는지 검사한다. 오래된 새 실행을 보류한 뒤 사용자 요청을 먼저 처리하고 최신 원문 전체로 원 계획을 다시 판단한다. **현재 작업 중지**는 그 작업의 다음 폰·앱 실행을 멈추고, 이미 제출된 웹 작업에는 중지 요청을 시도한다. 실제 클라우드 중지 확인과 Work의 native steer는 별도이며 아직 실계정에서 검증하지 않았다. 앱을 닫는 것을 이미 접수한 클라우드 작업의 취소로 취급하지 않는다. UI와 브라우저 연결이 종료되면 결과 수신은 지연되거나 미확인 상태가 될 수 있다.

휴대폰의 foreground service는 사용자에게 보이는 실행 유지 방식이다. 설정에서 **계속 유지**, **작업 중 유지**, **충전 중 계속 유지**를 선택한다. 계속 유지는 화면 꺼짐 상태에서도 120초 wake-lock을 1분마다 갱신하므로 배터리 사용이 늘 수 있다. 작업 중 유지는 유휴 때 해제한다. 실제 모드·충전·CPU 유지·최근 확인 시각을 상태에 표시하며 아직 삼성 기기의 배터리 사용량을 측정하지 않았다. Doze에는 별도 배터리 최적화 예외가 필요하다. 예외와 권한이 있어도 전원 꺼짐·강제 종료·통신 단절·OS 중단에서 매분 실행과 24시간 연속 동작을 보장하지 않는다. [실행 유지 방식](../docs/android-runtime-resource-modes.md)

Android 설정의 **강제 종료**는 일반 화면 닫기나 재부팅과 다르다. Android15는 강제 종료한 앱의 접근성 허용도 해제할 수 있다. 다시 열었을 때 **시작할 준비**에 접근성이 빠졌다고 표시되면 Android 설정에서 다시 허용한다. 앱이 사라진 OS 권한을 자동으로 부여한 것으로 처리하지 않는다.

## 검증 상태

0.4.0 통합 unit suite는1,260개 중1,243개 통과·선택형17개 제외·실패0개다. [최종 5년 원문 회귀](../docs/benchmarks/android-v040-five-year-memory-regression.json)는432/432개 출처 조건·144/144개 전체 패킷의0.3.2 동일성을 확인했다. 이 원문 fixture는 실제 native SQLite와 합성 기록을 사용하며 계정/MFA 실행은 별도 테스트다. 새 모델144개 답변 채점이나 실제5년 사용 결과가 아니다.

lint·API35 KVM CI·서명 APK와 다운로드 지문의 검증 결과는 [0.4.0 배포 기록](../docs/release-v040.md)에서 확인한다. 실제 Galaxy S24 Ultra 장기 운용·실계정 Work·외부 로그인·통화/문자 전달·일평균10%는 별도 측정 대상이다.

## 빌드와 검증

Linux x86_64 개발 환경에서는 공식 SHA256를 확인하는 도구 준비 스크립트를 사용한다.

```bash
./mobile/tools/build-android.sh ./mobile assembleDebug testDebugUnitTest
./mobile/tools/build-release.sh ./mobile assembleRelease testDebugUnitTest lintRelease
node --test mobile/tests/work-bridge.test.mjs
```

Android Studio에서는 `mobile`을 열고 SDK 35, JDK 17, Gradle 8.11.1을 사용한다. 기본 앱은 SDK 26 이상, target SDK 35다. 테스트는 인공 데이터·브라우저 fixture·Robolectric을 사용하며 실제 계정 로그인, 연락처·알림 수집, 외부 메시지, 결제는 실행하지 않는다.

Release 서명 개인키는 Git 밖의 전용 비공개 디렉터리에 저장한다. 공개 인증서와 지문은 `mobile/signing`에 있다. 같은 앱을 업데이트하려면 기존 개인키가 필요하므로 별도로 비공개 백업해야 한다. 공개 인증서가 있는 소스에서 개인키를 찾지 못하면 배포 스크립트는 다른 키를 생성하지 않고 중단한다. 개발용 debug 빌드는 별도로 만들 수 있다.

DOM 전송 선택자만 [codex-chatgpt-web](https://github.com/miuuyy/codex-chatgpt-web/tree/0b6087c5307c7a58adda9c420358f3f70d2035f5)의 접근을 참고했다. Electron, 데스크톱 브릿지, Codex CLI 실행기를 포함하지 않으며 MIT 고지는 앱에 제공한다. 구조와 검증 조건은 [Work 앱 설계](../docs/work-mobile-architecture.md)에 기록한다.
