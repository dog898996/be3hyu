# 호영이 Android 앱

휴대폰 앱이 ChatGPT Work 임시채팅에 요청을 전달하고 대화, 기억과 작업 파일은 폰에 보관한다. 사설 VM이나 상시 PC는 사용하지 않는다. 전용 H 아이콘의 release APK를 제공하며, 실제 계정의 Work UI와 갤럭시 장시간 실행은 설치 후 검증해야 한다.

## 설치와 연결

1. 빌드된 호영이 APK를 설치하고 앱을 연다. 앱 회원가입은 없다.
2. **Work** 탭에서 본인 ChatGPT에 로그인한다. 이 인증은 ChatGPT 구독 연결이며 앱 회원가입과 별개다. Google 등의 로그인 제공자가 임베디드 브라우저를 거부하면 우회하지 않고 지원되는 로그인 방법을 확인한다.
3. Work와 임시채팅, GPT-6.1 Sol, Medium, Fast를 선택하고 **선택 확인**을 누른다. 확인하지 못한 상태에서 일반 Chat이나 다른 모델로 바꾸어 보내지 않는다.
4. **검증 요청**으로 클라우드 코드 도구와 최소 휴대폰 상태 확인을 요청한다. 요청이 접수되었다는 것과 실제 클라우드 도구 검증 통과는 구분한다.
5. **권한** 탭에서 기본권한을 요청하고 원하는 특수권한의 Android 설정을 연다. 앱 도구는 기본 허용하며 같은 탭이나 대화로 기능별 사용 여부를 바꾼다.
6. **설정**에서 계속 맡길 목표를 정하고 **자율 모드 켜기**를 누른다. 새 설치의 AI 판단 기본 간격은 5분이고 폰의 로컬 상태 확인은 1분이다. 기존에 바꾼 간격은 유지한다. 진행 중 작업과 중복해서 시작하지 않으며 상시 알림의 중지 버튼으로 자율 호출을 끌 수 있다.

사이드로드 APK의 알림 접근·접근성 설정이 제한되면 Android 앱 정보의 **제한된 설정 허용**이 필요할 수 있다. 이 선택은 사용자가 직접 수행한다. 실제 권한 부여 상태를 도구 실행 때 다시 확인한다. root, 기기 소유자 또는 시스템 서명 권한은 일반 앱 설치로 제공되지 않는다. [권한별 기능과 제한](../docs/android-permissions.md)

### 갤럭시의 ‘자동 차단 기능으로 설치 차단’

**출처를 알 수 없는 앱 설치**가 허용되어 있어도 삼성 **보안 위험 자동 차단(Auto Blocker)**이 켜져 있으면 외부 APK 설치를 별도로 막는다. 이 문구만으로 APK가 악성코드라는 판정은 아니다. 본인이 설치하려는 APK를 확인한 뒤 **설정 → 보안 및 개인정보 보호 → 보안 위험 자동 차단**을 잠시 끄고 설치한 다음 다시 켠다. Play Protect는 유지한다. 이미 출처 불명 설치를 허용한 설치 앱의 설정을 반복해서 바꿀 필요는 없다. [삼성 설치 차단 안내](https://www.samsung.com/us/support/troubleshoot/TSG10001914/)

아이콘이나 release 서명을 바꿔도 이 OS 설치 정책을 해제할 수 없다. 현재 0.3.0 개발 소스는 기존 권한을 삭제하지 않고 Wi-Fi·Bluetooth의 일반 권한 3개를 추가한 40개다. 알림 접근·접근성 서비스도 유지한다. 설치 후 Android의 **제한된 설정 허용**과 원하는 특수권한을 별도로 부여한다. [Android 제한된 설정 안내](https://support.google.com/android/answer/12623953?hl=en)

이미 debug APK를 설치했다면 release의 서명이 달라 바로 업데이트할 수 없다. 기존 앱의 파일 탭에서 외부 백업을 내보낸 뒤 debug 앱을 제거하고 release를 설치·복원한다. 설치가 차단되어 기존 앱이 없는 경우에는 백업·제거 단계가 필요 없다.

## 기억과 파일

대화 원문, 출처가 있는 기억과 정정 이력은 내부 SQLite에 저장하고 큰 원문은 `filesDir/originals`, 작업 파일은 `filesDir/projects`에 보관한다. 첨부 원본은 해시를 붙인 불변 파일로 남긴다. 재생성 가능한 캐시와 구분하므로 일반 캐시 삭제로 지워지지 않는다. 앱 데이터 삭제·제거·폰 초기화 전에 **파일** 탭의 백업을 외부에 내보낸다. 백업에는 ChatGPT 로그인 쿠키와 브라우저 프로필을 넣지 않는다. [원문·첨부 보존](../docs/attachment-originals.md)

**기억** 탭에서 원문을 확인한 뒤 **AI 기억에서 제외** 또는 **원문·파생기록 삭제**를 선택할 수 있다. 제외는 원문을 남긴 채 이후 모델 조회를 막는다. 삭제는 관련 답변·기억 수정 이력·관리하는 로컬 복사본을 함께 정리하고 실제 완료·대기 범위를 표시한다. 같은 설치에서 옛 백업을 복원해도 제외·삭제 정책을 적용한 뒤 앱을 준비 완료로 전환한다. 제공자 서버나 이미 내보낸 백업의 삭제를 완료했다고 표시하지 않는다. 앱 제거·데이터 초기화로 정책도 사라지는 경우는 현재 보장 범위 밖이다. [제외·삭제 동작과 검증 범위](../docs/source-privacy-and-deletion.md)

사진·영상·음성·문서와 일반 파일은 Android 파일 선택기로 가져와 내부에 복사하고 대화에 첨부한다. 첨부 원본은 최대 64 MiB까지 그대로 보존한다. 브릿지가 실제 Work에 전달하는 예산은 한 파일 10 MiB, 총 20 MiB, 최대 8개다. 큰 사진은 원본을 남기고 예산에 맞는 별도 이미지 사본을 만들며 원본 해시·전송 해시·변환 여부를 모델과 기억에 구분해 전달한다. 영상·음성·문서 등의 바이너리는 자르거나 압축 변환하지 않고 정확한 바이트를 전달할 수 있을 때만 보낸다. Work 파일 입력이 해당 형식을 받지 않거나 업로드 준비 상태를 확인하지 못하면 파일을 빼거나 텍스트만 대신 보내지 않는다. 앱 파일 보관 기능은 서비스의 모든 형식·크기 지원을 뜻하지 않는다.

일반 작업 파일 보관은 한 파일 512 MiB까지다. 백업 압축본과 복원 전개 데이터는 각각 기본 64 GiB 한도로 스트리밍하며 설정에서 1~64 GiB로 바꿀 수 있다. 실제 저장 공간·외부 제공자 파일 제한은 별도이므로 진행 중 실패와 복원 반영 여부를 표시한다. 결과 파일은 앱 도구의 파일 쓰기 또는 지원되는 ChatGPT HTTPS 다운로드를 통해 저장한다. blob 다운로드나 지원되지 않는 서명 URL은 직접 저장해 가져오는 경로를 사용한다.

원문을 삭제하고 요약으로 대체하지 않는다. 전체 키워드 검색에 실제 공개 ONNX 모델의 폰 내부 512차원 의미 검색을 결합한다. 약 138MB 모델은 비종량 네트워크에서 체크섬을 확인해 받으며, 임베딩 계산용 외부 API 요금은 없다. native ANN 후보의 원래 F32 벡터를 재정렬하고 원문 해시·기간·현재 권한을 확인한다. 모델이나 색인이 준비되지 않았으면 기존 원문 검색을 유지하고 준비 범위를 표시한다.

출처별 검토 범위, 중요한 선호, 정정 revision, 기간, 별칭, 진행 중 목표를 따로 관리해 오래된 관련 원문을 다시 찾는다. 새 원문 검토와 사진 분석은 구분하며, 사진 원본 저장만으로 읽고 이해했다고 표시하지 않는다. 일반 대화에 미검토 원문을 한꺼번에 붙이지 않는다. 자동 판단에는 직렬화된 작은 검토 배치를 함께 넣어 긴 작업 때문에 기억 정리가 밀리지 않게 하고, 실제 유효한 검토 ACK만 진도로 기록한다. 별도 검토 요청도 유지한다. 검토 원문과 주변 대화의 실제 출처는 답변·작업 영수증·목표에 연결하며 제외·삭제·현재 권한을 전송과 결과 반영 시 다시 확인한다.

1~2년 설계의 검증은 합성 대량 자료·공개 검색 자료·기억 추출 probe로 나눠 공개한다. 365회 가상 세션의 저장·정정·조회 시나리오와 독립 모델의 선택된 문맥 독해도 각각 기록한다. 1년 20MB나 완전한 회상을 보장하지 않는다. 백만 합성 텍스트만으로도 DB와 WAL이 약 510MiB였으며 사진·벡터·원문 spool은 별도다. [연구·측정 범위](../docs/memory-research.md), [실제 모델 probe](../docs/model-memory-evaluation.md), [365회 시뮬레이션](../docs/longitudinal-memory-product-benchmark.md)

사용자가 업로드한 **세션과 기억처리** RFC v1.2 원문은 1,034줄 전체를 읽었다. SHA-256은 `4b778bdb7d71abc838bafcffa05bf83c2b105ad4e2837ce620cb32857ef21194`다. [항목별 구현·검증 대조](../docs/memory-rfc-integration-plan.md)와 [최신 5년 모의 기록 결과](../docs/five-year-memory-final-source-v7-results.md)에 구현 범위와 미검증 항목을 구분해 기록한다. 원문 검색, 실제 답변 채점, 앱 전송, 실제 폰·Work 실행 결과는 별도 증거로 확인한다.

## 실행과 복구

전송 전에 원문·요청 ID·첨부·실행 저널을 저장한다. 같은 입력의 접수·완료 이벤트와 폰 도구 실행 결과를 분리하고, 프로세스 중단·확인되지 않은 전송은 자동 반복하지 않는다. 명시적 재시도는 새 시도 ID를 사용하되 원 요청과 도구 영수증을 이어 받아 같은 부작용을 반복하지 않게 한다.

백업에서 되살린 미완료 요청은 확인 대기로 격리한다. 복원은 이미 실행한 일을 다시 실행했다는 뜻이 아니며 자율 모드는 사용자 확인 후 켠다. 작업이 진행 중이거나 결과가 미확인인 상태에서는 복원으로 실행 기록을 덮어쓰지 않는다.

사용 한도는 실제 서비스 안내로 판단하고 한도 소진을 앱 자체 메시지로 알린다. 유료 API·사설 VM·크레딧 자동 구매로 전환하지 않는다. 사용자의 재시도 선택은 실제 한도 회복의 증거로 표시하지 않는다.

새 사용자 입력은 즉시 저장하고 이전 전송 승인과 폰·앱 도구 제안이 그 입력보다 오래됐는지 검사한다. 오래된 새 실행을 보류한 뒤 사용자 요청을 먼저 처리하고 최신 원문 전체로 원 계획을 다시 판단한다. **현재 작업 중지**는 그 작업의 다음 폰·앱 실행을 멈추고, 이미 제출된 웹 작업에는 중지 요청을 시도한다. 실제 클라우드 중지 확인과 Work의 native steer는 별도이며 아직 실계정에서 검증하지 않았다. 앱을 닫는 것을 이미 접수한 클라우드 작업의 취소로 취급하지 않는다. UI와 브라우저 연결이 종료되면 결과 수신은 지연되거나 미확인 상태가 될 수 있다.

휴대폰의 foreground service는 사용자에게 보이는 실행 유지 방식이다. 설정에서 **계속 유지**, **작업 중 유지**, **충전 중 계속 유지**를 선택한다. 계속 유지는 화면 꺼짐 상태에서도 120초 wake-lock을 1분마다 갱신하므로 배터리 사용이 늘 수 있다. 작업 중 유지는 유휴 때 해제한다. 실제 모드·충전·CPU 유지·최근 확인 시각을 상태에 표시하며 아직 삼성 기기의 배터리 사용량을 측정하지 않았다. Doze에는 별도 배터리 최적화 예외가 필요하다. 예외와 권한이 있어도 전원 꺼짐·강제 종료·통신 단절·OS 중단에서 매분 실행과 24시간 연속 동작을 보장하지 않는다. [실행 유지 방식](../docs/android-runtime-resource-modes.md)

## 빌드와 검증

Linux x86_64 개발 환경에서는 공식 SHA256를 확인하는 도구 준비 스크립트를 사용한다.

```bash
./mobile/tools/build-android.sh ./mobile assembleDebug testDebugUnitTest
./mobile/tools/build-release.sh ./mobile assembleRelease testDebugUnitTest lintRelease
node --test mobile/tests/work-bridge.test.mjs
```

Android Studio에서는 `mobile`을 열고 SDK 35, JDK 17, Gradle 8.11.1을 사용한다. 기본 앱은 SDK 26 이상, target SDK 35다. 테스트는 인공 데이터·브라우저 fixture·Robolectric을 사용하며 실제 계정 로그인, 연락처·알림 수집, 외부 메시지, 결제는 실행하지 않는다.

Release 서명 개인키는 Git 밖의 전용 비공개 디렉터리에 저장한다. 공개 인증서와 지문은 `mobile/signing`에 있다. 같은 앱을 업데이트하려면 기존 개인키가 필요하므로 별도로 비공개 백업해야 한다. 공개 인증서가 있는 소스에서 개인키를 찾지 못하면 배포 스크립트는 다른 키를 생성하지 않고 중단한다. 개발용 debug 빌드는 별도로 만들 수 있다.

DOM 전송 선택자만 [codex-chatgpt-web](https://github.com/miuuyy/codex-chatgpt-web/tree/0b6087c5307c7a58adda9c420358f3f70d2035f5)의 접근을 참고했다. Electron, 데스크톱 브릿지, Codex CLI 실행기를 포함하지 않으며 MIT 고지는 앱에 제공한다. 구조와 검증 조건은 [Work 앱 설계](../docs/work-mobile-architecture.md)에 기록한다.
