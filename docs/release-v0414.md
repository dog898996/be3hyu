# 호영 0.4.14 — Work 답변 수집·재연결·연결 메뉴 수정

사용자 진단에서는 열린 대화에 원래 요청과 답변을 모두 찾았지만 `authenticated:null` 때문에 읽기 전용 답변 복구가 중단됐다. 이 로그인 표시 검사와 기존 답변 회수를 분리했다.

- 로그인 표시가 접히거나 관찰 기한이 지나도 기존 요청에 대응하는 완료 답변을 회수한다. 명시적 로그아웃·계정 변경 중에는 다른 계정의 결과를 섞지 않는다.
- 일반 글, 코드, 표, Markdown 틀이 없는 응답, 임베드의 노출된 설명·주소를 수집한다. 외부 임베드의 접근 불가능한 내부 내용까지 읽었다고 주장하지 않는다.
- 새 전송에는 원문을 복제하지 않는 정규화 SHA-256 연결 증거를 저장한다. 문서가 다시 생성돼도 일반 글 답변을 원래 요청과 대응할 수 있다. 업데이트 전 요청은 기존 프로토콜 ID 또는 살아 있는 브라우저의 원문 대응 증거로 복구한다.
- 불명확한 요청은 이미 나온 답변을 자동으로 확인한다. 관찰이 오래 이어지면 확인 간격을 늘린다. 답변 복구가 요청을 다시 전송하거나 이전 도구·기억 변경 제안을 재실행하지 않는다.
- 메시지 준비 중 연결 정보가 만료되거나 모델 선택창이 변해도 준비한 원문과 작업의 모델 선택을 유지하고, 준비 완료 관찰 뒤 이어서 전송한다.
- Work 화면에 연결·재연결·상세정보를 표시하고, Work/대화의 ⋯ 메뉴 맨 아래에 도움말을 추가했다. 답변 대기·가져오기 상태도 대화 화면에 표시한다.

`직접 삭제한 대화 확인`은 웹에서 사용자가 이미 삭제한 사실을 앱에 알려, 실패한 세션 정리를 마치는 기능이다. 버튼 자체가 대화를 삭제하거나 답변을 가져오지 않는다. 실제 삭제 확인이 필요한 경우에만 표시하며, 답변 수신 문제는 자동 확인·재연결로 처리한다. 폰의 기록·기억 DB를 지우지 않는다.

## 확인 범위

관련 JVM 80개, production bridge를 사용하는 Chromium DOM 회귀 102개가 통과했다. release/debug/Android test APK 빌드, 기존 서명·48개 manifest 권한·네이티브 패키징을 확인했다. 테스트 컴파일의 구형 Android Java API 사용과, Fast 고정·작업 도중 라우팅 변경·옛 프롬프트 서두를 전제하던 테스트도 현재 제품 동작에 맞췄다.

Android 35 독립 가상 기기 5개(작은 화면·큰 글자·영어/회전·백그라운드·태블릿)에서 연결 관련 10개 시나리오씩, 합계 **50/50 통과**했다. [실행 원본](https://github.com/dog898996/be3hyu/actions/runs/38725259172)과 [검증 기록](benchmarks/android-v0414-verification.json)에 결과를 보관했다. 실제 사용자 Galaxy(Android 36)와 로그인된 최신 ChatGPT 계정은 이 환경에서 실행하지 않았다. 유료 모델 요청은 하지 않았다.

기존 0.4.13 전체 탐색 검사에서 남았던 다른 기능의 실패를 이번 한정 검사 통과로 해결됐다고 간주하지 않는다. [이전 검사 범위와 제한](release-v0413.md)을 함께 참고한다.
