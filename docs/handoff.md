# 호영이 개발 인수 기록

## 2026-10-13 고정 Cloud 실행 구조와 native 엔진

최신 요구는 사용자가 CLI 기능을 고르지 않아도 충족할 구조를 개발자가 선택하고, 작업을 Cloud에서 수행하며 폰 접속과 대화 세션 변경으로 끊지 않는 것이다. `owner-cloud-resident-execution-2026-10-13` revision에 원문과 출처를 연결했다. 폰은 대화·설정·진행·조향을 담당하고 고정 Cloud VM이 실행기·60초 판단·공식 Codex app-server·브라우저·영구 데이터를 유지한다. 구독 Cloud task를 매번 생성하는 경로를 상주 worker로 사용하지 않는다. [구조](cloud-agent-architecture.md)와 [운영 절차](native-cloud-operations.md)를 따른다.

`ASSISTANT_ENGINE=codex-native` 선택 시 새 `NativeCloudRuntime`을 사용한다. 기존 엔진도 보존한다. `CodexAppServerClient`는 공식 stdio JSON-RPC를 지속 프로세스로 연결한다. native thread와 turn이 Codex 기본 도구를 실행하고 앱 기억·브라우저·설정·메시지·목표 도구를 연결한다. 실제 모델·medium·Fast 응답 설정이 요청과 일치해야 turn을 시작한다. native 자동 기억 추출은 사용량·삭제 동기화 검증 전까지 끄며 앱 원문과 출처가 있는 영구기억은 유지한다.

- 폰 HTTP 연결 종료는 작업 중단 신호가 아니다. 대화 변경은 thread 대응만 변경하며 worker ID와 작업 경로는 유지한다.
- 작업 중 새 입력은 native `turn/steer`로 전달하고 접수 응답과 실제 완료를 구분한다. 작업 수정·명시적 중단은 matching turn에 전달한다.
- 앱 text 재전송 큐는 저장된 메시지 ID를 사용한다. 서버 재시작 뒤 재전송도 이미 접수된 메시지·작업을 중복 생성하지 않는다. 다른 내용으로 같은 ID를 재사용하면 거절한다.
- 한도는 모델 없는 조회로 확인한다. 불명확한 복구·시작·조향·완료 결과를 성공으로 표시하거나 같은 행동을 자동 반복하지 않는다. native 기록을 페이지로 조회해 실제 완료를 확인한다.
- 공식 기기 로그인으로 새 인증이 저장되면 idle 상태에서 resident 인증 캐시를 다시 로드한다. 진행 중 작업에서는 갱신을 지연하고 같은 worker·thread 대응을 유지한다.
- 권한 철회 시 native full access를 앱 도구의 개별 권한만으로 완전히 격리한다고 표시하지 않는다. 지원할 수 없는 권한 조합은 native 실행을 중단·대기하며 기본 모두 허용 구성은 native 작업을 수행한다.

최신 전체 테스트 **201개가 모두 통과**했고 문법·diff 검사도 통과했다. native transport 18개, native runtime 25개, 실제 loopback HTTP와 native protocol 대역 통합 6개, 앱 재접속 7개, 브라우저 중단 2개가 포함된다. 격리한 Chromium UI에서 오프라인 입력 재로드·접수 응답 유실 뒤 상태 대조·인증 실패 후 자동 요청 대기를 확인했고 JS 오류는 없었다.

설치된 실제 Codex CLI에 새 빈 전용 home으로 `initialize`, `account/read`, `config/read`만 보내 초기화와 설정 응답을 확인했다. 계정은 없음으로 관측했으며 모델 turn·로그인·Cloud 작업은 만들지 않았다. 이는 실제 모델 생성·사이트 계정 작업·24시간 운영 검증이 아니다.

과거 0원 서버 요구보다 나중에 허용한 **Cloud 서버 월 1만~2만원**을 `owner-cloud-hosting-budget-2026-10-13`으로 출처와 함께 반영했다. 서버 운영 상한은 **20,000 KRW**, 유료 모델 API·크레딧 자동 구매와 구분한다. 실제 서버 구매·유료 전환은 수행하지 않았다. 뒤의 예산 미변경·0원 언급은 당시 이력이다.

실제 운영 VM 배포·로그인·장시간 작업, Android APK·사진 입력·push·휴대폰 기기 도구는 미완료다. 이전 설치 아카이브 `526e47e`에는 새 엔진이 없으므로 최신 소스로 다시 패키지해야 한다. 한 데이터 디렉터리에는 실행기를 하나만 운영한다. 실제 호스트 장애에서 RAM·프로세스 유지와 완전 무중단을 보장하지 않으며, 감독·영구 저장·기록 확인 후 복구를 사용한다.

## 2026-10-13 최신 범위: 전용 앱과 CLI 재검토

사용자는 한 명만 쓰는 전용 채팅앱으로 개발하며 Instagram DM 수신·다른 사람 권한·앱 회원가입이나 로그인은 필요 없다고 정정했다. `owner-single-user-app-2026-10-13` revision에 원문과 출처를 연결해 한 번 반영했다. 이후 수동 설정을 재시작마다 덮어쓰지 않는다. 기존 원문·기억·레거시 연결 정보는 보존했다. 이전 기본 지속 목표와 설명이 정확히 일치하는 경우에만 앱 기반 목표로 바꾸며 사용자 편집 목표는 유지한다.

- 로컬 앱은 채팅 화면으로 바로 열린다. 일반 화면에서 Instagram 설정을 제거하고 Codex 모델 구독 연결은 최초 한 번 필요한 별도 인증으로 표시했다. 외부 공개 서버의 접근 토큰은 앱 회원 계정과 구분한다.
- 앱 입력·답변·선톡·한도 안내는 단일 사용자 앱 경로를 사용한다. 메시지와 outbox는 원자적으로 저장하며 재시작·재시도에서 중복을 방지한다. 영수증은 `local-app-storage`이며 push 도착이나 화면 읽음 확인으로 표시하지 않는다. 꺼진 Instagram은 poll·발송·읽음에 연결되지 않고 비활성화 중 도착한 관측 결과도 버린다.
- 일반 로컬 CLI 대화 기록과 ChatGPT의 보통 채팅 목록은 별개다. 정상 native 원문을 유지하도록 불필요한 `--ephemeral` 기본값을 제거했다. 명시적 `ephemeral:true`만 native 세션 보관을 끈다. 실제 모델 생성으로 파일 생성을 관측한 상태는 아니며 서버 추론·제공자 보관이 없다고 보장하지 않는다.
- 한도 조회는 모델 호출 없이 `account/read`와 `account/rateLimits/read`를 사용한다. 정상 ChatGPT 계정과 구조화 응답을 확인하고 비밀·원본 오류를 반환하지 않는다. 한도 소진 후에는 새 조회의 `quotaRecoveryVerified === true`가 있어야 모델 작업을 재개한다. 리셋 시간 경과·조회 실패·알 수 없는 이용 상태만으로 복구라고 표시하지 않는다. 새 입력과 대기 작업은 보존하며 한도 안내 중복을 막는다.
- 공개 CLI 소스와 공식 문서로 TUI·exec·app-server·Cloud 경로, 인증 캐시·자동 갱신, 원문 파일·AGENTS.md·Memories·조향 프로토콜을 검토했다. 다음 핵심 연결은 공식 app-server의 지속 thread·turn과 기본 도구를 사용한다. 현재 exec 기반 연결을 전체 native 작업 엔진으로 전환하거나 자동 Memories를 활성화한 상태는 아니다. [CLI 심층 검토](codex-cli.md)에 근거와 제한을 정리했다.

격리한 UI 검토에서 채팅 우선 화면·앱 로그인 창 없음·Codex 인증 구분·고급 설정 접힘·JS 오류 없음을 확인했다. 최신 전체 자동화 테스트 **141개가 모두 통과**했고 JavaScript 문법·diff 공백 검사도 통과했다. 새 검증은 앱 경로·선톡 원자성·중복·재시작·조향, 한도 조회·불명확한 복구·비밀 제거, 기존 목표와 수동 설정 보존을 포함한다. 자동화 테스트는 native RPC·모델·사이트 응답 대역을 사용한다. 이번 변경에서 실제 로그인·모델 생성·Cloud 작업 제출·운영 배포는 수행하지 않았다. Android APK·사진 입력·push·휴대폰 권한 도구·24시간 운영은 미완료다. 이전 설치 패키지 `526e47e`에는 이번 변경이 없으므로 설치 전에 최신 소스를 패키지로 만들어야 한다.

운영비 0원은 아래 과거 결정이며 이후 사용자는 월 1만~2만원 예산도 허용했다. 이번 변경은 운영 예산 설정·유료 전환·구매 크레딧이나 자동 충전을 수정하지 않았다. VM 확보의 아래 상태는 당시 관측 이력이며 이번 CLI 검토에서 현재 상태를 재조회하지 않았다.

## 당시 계획한 배포 순서

아래는 Instagram DM을 대화 수단으로 사용하던 당시 계획이다. 최신 전용 앱 범위에서는 5번의 Instagram 연결을 대화에 요구하지 않는다. 설치 소스와 현재 운영 상태를 확인한 뒤 최신 앱 경로로 검증한다.

1. Oracle 가입과 공식 콘솔 인증은 완료했다. 실제 홈 리전은 Japan Central (Osaka)다. 무료 체험 크레딧에 의존하지 않고 Always Free 범위만 사용하며 Pay As You Go로 전환하지 않는다.
2. 홈 리전의 무료 VM 자리를 실제 생성 요청으로 확보한다. 공식 Compute Capacity Report에서 A1 2 CPU/6GB, A1 1 CPU/6·3·2GB의 기본 배치와 각 Fault Domain 1–3, AMD E2.1.Micro 1GB가 모두 `OUT_OF_HOST_CAPACITY`였다. 이후 A1 1 OCPU·6GB·부팅 100GB의 첫 실제 생성도 용량 부족으로 거절됐다. 로컬 작업의 종료를 확인한 뒤 상태를 이전했고, Resource Manager에서 실제 두 번째 요청과 대기를 확인했다. 이번 창이 종료된 뒤 자동으로 새 창을 만들지는 않는다. 재개는 이전 작업의 종료와 최신 비공개 체크포인트를 확인한 뒤 수행하며, 옛 ZIP·로컬 manifest를 그대로 다시 실행하지 않는다. 사용자가 허용한 0원 범위에서만 확보하고 유료 모양으로 대체하지 않는다.

4. 운영 서버의 관리 토큰으로 UI에 연결하고 공식 ChatGPT 기기 인증을 새로 한다. 실제 모델·추론·Fast와 무해한 첫 작업을 확인한다.
5. 할당 Instagram 계정에 로그인하고 주인 DM 주소를 지정한다. 주인 조향, 외부 명령 거부, 작업 중 수신·발송 영수증을 실제로 확인한다.
