# 호영 0.4.9 — Fast를 켠 뒤의 Work 연결 확인

사용자의 0.4.8 진단에서는 모델과 Medium은 확인됐지만 속도가 미확인이었다. 팝업에 있던 속도 제어는 `menuitemcheckbox`, `aria-checked=true`, 문구는 `Standard 모드 활성화`였다. 앞서 제공된 꺼진 상태는 `Fast 모드 활성화`, `aria-checked=false`였다.

0.4.8은 Fast를 켜는 클릭까지 수행한 뒤 바뀐 문구를 인식하지 못했다. 기존 재현 검사는 활성화 문구가 그대로 남는 체크박스만 포함했으므로 실제 화면의 전환을 놓쳤다. 전체 개인 진단은 저장소에 복사하지 않았다.

## 수정

- Fast 체크박스의 켜진 상태에서 표시되는 `Standard 모드 활성화`를 인식한다. 버튼 문구는 클릭할 때 바뀔 목적지이며, 체크 상태가 현재 Fast 상태를 나타낸다.
- 이미 Fast가 켜진 새 문서에서도 상태를 읽는다. Standard 요청은 한 번만 끄고, 반복 연결은 다시 토글하지 않는다.
- 상태 변경 시 브라우저가 버튼 DOM을 교체해도 같은 규칙으로 다시 읽는다. 확인을 마치면 기존 경로로 선택창을 닫고 전송한다.
- 값이 충돌하거나 확인되지 않은 경우 준비 완료라고 추측하지 않는다. UltraFast를 선택하지 않는다.

수정 범위는 브라우저 연결의 속도 제어 인식이다. 기존 대화방 비우기·원문·장기기억·모델 라우팅·백업·진행 중 작업 처리는 변경하지 않았다.

## 검사

이번 진단의 문구 전환을 반영한 두 재현 검사는 수정 전 실패했다. 수정 후 자동으로 선택창 열기, Fast 켜기, 문구 전환 확인, 선택창 닫기, 전송 접수와 답변 수집을 검사한다. 켜진 상태에서 시작, Fast 끄기, 재연결과 DOM 교체도 포함한다. 모든 브라우저 검사는 로컬 재현이며 실제 계정 호출이 아니다.

기존 앱 위에 업데이트한 뒤 **Work → 연결**을 누른다. 실제 Galaxy에서의 최종 연결은 이 개발 환경에서 직접 확인할 수 없으므로 재현 검사 결과와 구분한다.

브라우저 연결 검사 **88/88**, 서명 릴리스 빌드·필수 lint·APK 서명 검사·패키징된 연결 파일 6개의 원본 일치 확인을 통과했다. 이번에 추가한 재현 두 검사는 수정 전 모두 실패하고 수정 후 통과했다. 네이티브 코드는 변경하지 않아 네이티브 전체 검사와 장기기억 시뮬레이션을 반복하지 않았다. 유료 모델 호출은 0회다.
