# Android grant → implemented capability audit

This audit covers all **48 `uses-permission` declarations** in [AndroidManifest.xml][manifest], plus component binding/broadcast permissions and user-controlled special accesses. It audits the current source tree, not merely default-enabled tool switches. A manifest grant, tool invocation, accepted Android request, completed callback and externally verified outcome are different evidence levels. The runtime currently exposes117 tools:90 phone,9 account/MFA,3 app-file and15 memory/task/settings tools. The exact same runtime catalog supplies model definitions and the permission UI; the native account/UI regression verifies one persisted owner control per actual catalog entry.

`C` below means an actual Android API call exists in the linked source. `U` identifies synthetic/Robolectric regression source, not proof of a physical effect. `N` identifies native instrumentation. **No Galaxy S24 Ultra physical-device validation has been performed by this audit.**

The final local source `9e04a61771e9ad793106c28face89446e235335d` completed1,260 unit cases:1,243 passed,17 selected opt-in cases skipped, zero failures/errors. This includes the latest accessibility identity, grant revocation, exact-account/MFA, full catalog/UI, native callback receipt and original recovery-reservation resumption regressions. Debug and signed release builds and lint passed with zero lint errors and27 warnings. [Local proof](benchmarks/android-v040-local.json), [signed APK proof](benchmarks/android-v040-apk.json). Focused runs overlap this full suite and must not be added to its count.

Final [run38550084173](https://github.com/dog898996/be3hyu/actions/runs/38550084173) passed25/25 product and33/33 total instrumentation cases plus every required shell restart/boundary assertion. Its commit4e7b929b has identical app code to the signed APK build9e04; only the driver/protocol changed. The final boundary records actual original-PID disappearance, autonomy foreground-service absence and accessibility revocation, allowing another PID only with its matching live Android-owned notification-listener binding. [Actual CI proof](benchmarks/android-v040-ci.json). Earlier failures, including38547659110 with33/33 instrumentation passes but a failed shell boundary, remain in [CI attempts](benchmarks/android-v040-ci-attempts.json). The final driver preserves real accessibility services under UiAutomation, checks actual guest network interfaces and `ConnectivityManager` state, and separates explicit force-stop permission revocation from normal process/crash/boot recovery.

Dangerous runtime permissions and supported special grants are mandatory under this owner's onboarding policy. Normal install-time permissions do not receive impossible runtime prompts. Actual grants are rechecked after settings return, restart, and revocation. Unsupported hardware/OS-only access is explained rather than counted as granted. SMS/call-log installer eligibility is checked separately per permission; a non-default sideloaded app can be eligible. Unknown eligibility first receives an actual runtime request. A completed no-prompt denial can make an unknown, never-granted permission conditional, explicitly **ungranted and unverified**, with a settings retry. Observed prior grants remain required after revocation, and readable allowlist inclusion remains required even after denial. The permission setup gate and editable tool switches are independent. [Gate source][gate], [gate U][gate-test], [denied-gate N][gate-native].

The official [PackageInstaller.SessionParams documentation][installer-doc] says restricted permissions are initially allowlisted unless the installer changes the list. The public [PackageManager implementation contract][allowlist-source] permits querying each allowlist but can throw `SecurityException` without installer/privileged access. The implementation uses actual returned evidence and never claims an inaccessible list is empty or edits allowlists.

## Gaps and verification still required

- The original exact-alarm and Nearby-Wi-Fi declarations had no action consumer. New native reminder and local-only-hotspot tools now address those source-level gaps. The reminder fixture passed through actual AlarmManager delivery and durable receiver storage on offline API35. Physical Samsung reminders and local-only-hotspot operation remain unverified.
- Microphone, GPS/background-location delivery, radios/hotspot, torch/camera capture, actual calls/SIM information, overlay display, screen lock, vibration/volume/brightness and OEM battery survival require dedicated on-device outcomes. Synthetic tests and a checked permission gate cannot prove those effects.
- Native tests use a fresh disposable offline AVD and synthetic provider/UI fixtures. No real account, real contact, real message or phone call is used. The driver requires1 denied-setup +4 provider +20 full-grant checks, password/screenshot/exact-alarm proof markers, an independent actual `ConnectivityManager` offline preflight and the existing restart phases. The exact-alarm fixture explicitly disables notifications and model invocation.
- All installed-app capabilities remain subject to Android exposure. “Every applicable permission granted” does not mean root, unrestricted secure settings, reading another app's protected data, unlocking the phone, bypassing server authentication or overriding an OS-denied API.
