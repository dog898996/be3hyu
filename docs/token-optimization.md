# 호영 0.3.2 사용량 최적화

사용자 요구는 **사용량 화면의 전체 공유 한도를 기준으로 일평균 소비를 10% 이하로 줄이는 것**이다. 10%는 성과 목표이며 강제 예산 한도가 아니다. 목표 초과·반올림 오차·관측 만료를 이유로 대화, 자율 판단, 기억 검토나 진행 중 작업을 중단하지 않는다. 실제 공급자의 한도 소진과 접수 불확실성 처리는 별도로 유지한다. 사용자 요청과 그 후속 응답에는 Fast를 요청한다. Fast가 실제 즉답을 보장한다는 뜻은 아니다.

## 실행과 품질

| 요청 | 기본 설정 | 보호 조건 |
| --- | --- | --- |
| 사용자 대화·작업과 같은 root의 후속 응답 | 선택한 Sol 모델, Medium 이상/Fast | Light를 먼저 호출하지 않는다. 사용자가 지정한 더 높은 추론 수준을 보존한다. |
| 변동 없는 정기 판단 | Sol Light/Standard 후보 | 5분 주기를 유지한다. 새로운 폰 이벤트, 도래한 목표, 불확실한 상태, 미검토·누락·충돌 기억은 전송 전에 Medium으로 올린다. |
| 기억 추출·정정·개인화 | Medium 이상/Standard | 절약 모드를 꺼도 writer를 Light로 낮추지 않는다. 검토한 원문 범위만 기존 ACK 규칙으로 처리한다. |
| 실제 행동과 복잡한 문제 | Medium 또는 필요한 High 이상 | Light의 행동·기억 저장·검토 완료 제안은 native 실행 없이 같은 root의 후속 요청으로 승격한다. 승격은 추가 호출이므로 장부에 포함한다. |

Light의 완료 계약은 현재 requestId에 묶인 `idle`, 빈 사용자 메시지, 명시적 `NO_ACTION`과 근거다. 뜻이 불명확하거나 실행·메모·검토 ACK가 있으면 Medium 이상으로 넘긴다. 이는 의미적 오판을 완전히 탐지한다는 증거가 아니다. Work 내부 브라우저·클라우드 도구의 판단 전용 사용은 프롬프트 계약이며, 네이티브 앱이 그 모든 도구를 기술적으로 비활성화했다고 주장하지 않는다.

요청 준비 시 모델·추론·속도를 불변 스냅샷으로 잡는다. 브릿지는 초안·첨부·기존 실행이 없는 상태에서 명시적인 설정 메뉴를 선택하고 DOM 표시를 재확인한다. Theme의 Light/Standard는 설정 근거가 아니다. 미지원 설정은 조용히 다른 설정으로 바꾸지 않는다. 선택 결과가 불확실해지면 전송 전 원문을 보존하고 명시적 복구를 기다린다. 이미 접수된 Work 요청은 같은 방식으로 재전송하지 않는다.

## 문맥 절감

판단 전용 요청에는 59개 전체 기능 이름을 남기고 실행에 필요한 긴 도구 인자 명세·writer 예시를 생략한다. 실행 요청에는 전체 명세를 제공하므로 기능·권한 자체를 줄이지 않는다. 기본 정체성과 전체 사용자 지침, 현재 입력, 최신 정정, 필수 제약과 근거는 유지한다.

MemoryGateway는 동일 SQLite 스냅샷의 완전한 지침이 실제 프롬프트에 이미 존재한다는 정확한 문자열 증거가 있을 때만 procedural 중복을 제외한다. standingGoals는 필수 active 계층의 완전한 동일 값으로 대체한다. 원문·해시·변경 이력·삭제 및 제외 정책·5계층 조회 영수증·유효성 검사·검색 개수와 전체 예산은 줄이지 않는다. 중복 제거 진단은 native 쪽에만 남겨 진단 자체가 모델 입력을 늘리지 않게 한다.

같은 임시채팅의 이력, 서버의 캐시·압축·숨은 추론량은 앱이 완전히 제어하지 못한다. 따라서 새 프롬프트 문자 감소를 전체 토큰 감소나 구독 한도 감소로 환산하지 않는다. 현재 변경은 세션을 자동 초기화하거나 진행 중 클라우드 작업을 갈아타지 않는다.

## 성과 관찰

UsageBudgetLedger는 별도 private SQLite에 전송 준비, 실제 접수 영수증, 관측된 선택 상태, 결과와 사용량 화면 관찰을 저장한다. 반복 접수는 중복 집계하지 않고 이미 접수된 설정은 불변이다. 일반 기억 ZIP 복원이 이 장부를 과거로 되돌리지 않는다. 해결되지 않은 요청은 보존하고 완료 집계 이력은 32일로 제한한다. 이것은 앱 제거·데이터 삭제 이후의 사용량 장부 보존을 보장하지 않는다.

열려 있는 실제 Work 사용량 화면을 읽는 동작은 native 사용자 클릭으로 시작한다. 페이지 이동·AI 호출·실행 취소 없이 명시적인 Pro 주간 Work/Codex 풀의 비율과 시간대가 있는 reset 시각을 확인한다. 문서 세대·출처·nonce·시각·수치·근거 해시를 확인하고, 숨겨진 내용·대화 본문·여러 후보·애매한 날짜는 관측으로 인정하지 않는다. UI 변경으로 근거를 읽지 못하면 미확인이다. 계정 구분 이름은 사용자 라벨이며 `accountIdentityVerified:false`로 표시한다. 계정을 바꿀 때 같은 라벨을 재사용하면 동일 계정 소비라고 단정할 수 없다.

수동 입력은 `owner_reported`이며 공급자 확인으로 승격하지 않는다. 관측 사이의 같은 계정 공유 풀 변화와 표시 반올림 범위를 계산한다. 부분 관찰, 갱신 지연, 리셋 구간의 누락과 다른 Work/Codex 사용을 구분한다. 사용량 %는 토큰·API 달러·앱 단독 소비량이 아니다. `backgroundAllowed`와 `backgroundDecision.allowed`는 항상 true이며 최적화 목표가 호출 허가를 통제하지 않는다.

## 확인한 결과와 한계

[최종 로컬 기록](benchmarks/android-v032-optimization-local.json): Java 873개 중856개 통과, 선택형17개 제외, 실패·오류0개. Node259개 전부 통과하며 Work DOM58개를 포함한다. 7일·2,016개 무변화 슬롯의 예약·재시작·중복 방지 재생은 모의 접수 영수증을 사용한 스케줄러 시험이며 실제 AI2,016회 실행이 아니다.

같은 완전한 원문·해시와 59개 기능을 보존한 native fixture의 판단 프롬프트는 Medium/Standard24,521 UTF-16자에서 Light/Standard7,203자로 줄었다. 제거된 문자는17,318자, 남은 비율은 약29.4%다. 이 fixture는 미리 검토된 원문 상태를 사용하며 실제 모델 호출0회다. 토큰·구독 차감·답변 정확도 비교가 아니다. 새 정정·삭제·중복 제거·단계 전환·사용량 초과 후 계속 실행·선택 불확실성 복구를 별도로 검사했다.

실제 계정의 일평균10%, 실제 Work UI 호환성·서버 적용 모델, Light/Medium 의미 정확도 동등성, Galaxy S24 Ultra의 지연·24시간 운용은 아직 측정하지 않았다. 이전5년144문항 답변 채점을 이번 버전에서 새로 실행했다는 주장도 하지 않는다. 새 코드의 구조 검사와 원문 회귀를 실사용 정확도 검증으로 바꾸어 표현하지 않는다.
