# 호영 장기 기억과 휴대폰 비서 개발 기록

## 작업 목표

사용자는 1~2년의 대화·활동 원문을 보존하고, 기록이 쌓일수록 관련 증거를 더 정확히 회상하며 개인화되는 휴대폰 비서를 요청했다. 기본 이름은 호영이며, 사용자 추가 지침과 기능 권한은 앱과 대화에서 수정할 수 있어야 한다. 추가 서버·모델 API 비용은 허용하지 않는다. 약 6시간의 개발·검증을 요청했으며 실제 경과 시간과 검증 범위를 기록한다.

## 2026년 10월 13일 15시 50분 UTC 작업 시작

기준 버전은 GitHub `773023c`의 Android 0.1.1이다. 현재 저장소는 `/workspace/be3hyu`이며 이전 로컬 이력과 개인 서명키는 공개 저장소 밖에 보존한다. 저장·검색, 휴대폰 정보, 웹 연결, 빌드·Android 가상기기 검증을 병렬로 진행한다. 사용자 요청에 따라 질문을 기다리지 않고 비용 없는 개발을 계속한다.

Space의 공식 연결 도구로 자율 비서 개발 Space와 접근 가능한 모든 Page를 확인했다. 반환된 항목은 Space 루트와 과거 대화 Page이며, 「세션과 기억처리」 문서 본문이나 읽을 수 있는 파일 참조는 아직 반환되지 않았다. 이는 문서가 없다는 증거가 아니다. 기존 Library 공유 링크의 로그인 제한도 해결됐다고 기록하지 않는다. 확보된 사용자 요구와 1차 연구를 기준으로 독립적으로 개선하면서 원문 확보를 계속 시도한다.

## 초기 점검에서 확인한 문제

- 현재 기억 검색은 키워드 후보 200개와 제한된 문맥에 의존하고, 기본 판단 간격은 60초다. 5분 설정은 가능하지만 새 기본값과 사용자 변경 유지 정책을 분리한다.
- 저장소 v1은 후속 schema migration 경로가 없고, 기존 백업은 전체 기록을 메모리에 읽어 크기·행 수 상한에 도달할 수 있다. 장기 사용을 위한 인덱스와 스트리밍 백업이 필요하다.
- Runtime의 DB transaction과 synchronized store 호출 순서가 백업과 다르면 교착 상태가 생길 수 있다. 공통 transaction helper로 순서를 통일한다.
- 큰 웹 응답이 전달 한도를 넘으면 조용히 버려질 수 있다. 원문을 조각으로 보존하고 불완전한 수신을 완료로 기록하지 않는다.
- 임시 Work 작업 관찰을 잃으면 공식 재접속 경로를 확보하지 못할 수 있다. 접수 불명·결과 미확인은 보존하며 부작용이 있는 작업을 자동 반복하지 않는다.

## 검증 원칙

실제 코드 테스트, 합성 장기 기억 검색, 실제 Android 가상기기, 실계정 Work와 삼성 실폰 검증을 구분한다. 합성 730일 데이터가 실제 2년 사용 품질을 증명한다고 설명하지 않는다. 경쟁 제품보다 우수하다는 결론에는 비교 가능한 평가가 필요하며, 현재 목표와 확인 결과를 구분한다. 변경 묶음마다 실행한 검증·실패·수정·GitHub 커밋을 이어서 기록한다.

## 17시 03분 UTC — 장기 보존·실제 모델·비동기 처리 검토

기존 원문을 지우지 않는 schema 2, 원문 파일 분리, 전체 FTS 검색, 출처 hash와 기억 revision, 스트리밍 백업을 구현했다. 알림·센서 콜백은 SQLite 잠금에 기다리지 않도록 fsync spool에 먼저 저장하고 순차 적재한다. 휴대폰 기능은 실제 OS·도구 허용 상태를 확인하며, 회수된 관찰은 검색과 파생 기억의 자동 문맥에서 제외한다. 중앙 Android 빌드·회귀는 아직 진행 전/진행 중이다.

공식 배포 모델 distiluse-base-multilingual-cased-v2의 고정 revision과 SHA를 확인했고, Android ONNX Runtime으로 실제 512차원 의미 벡터를 생성하는 코드를 작성했다. 약 138MB 모델은 Git에 넣지 않고 비종량 네트워크에서 검증해 다운로드한다. 호스트 Python의 한국어·영어 의미 비교 8개는 모두 관련 문장이 무관 문장보다 가까웠다. 이는 작은 실제 모델 sanity 검사이며 실기기 속도·종합 기억 정확도를 증명하지 않는다.

합성 100,000개 원문 실제 SQLite 검색에서는 수동 gold 30질문의 Recall@10이 1.0, DB+WAL 약 52.4MiB였다. 공개 LongMemEval oracle 자료를 6유형 40문항으로 균형 추출한 초기 키워드 검색은 source Recall@20 0.525, 모든 gold를 찾은 질문 18/40이었다. 이 낮은 결과를 별도로 남기며 실제 의미 모델을 붙인 개선 측정을 준비한다. 모델 답변·자동 기억 추출을 평가한 결과는 아니다.

독립 검토에서 일반 답변에 인용한 hoyoung 예시를 실행할 수 있는 문제, 렌더링된 코드 블록의 fence 소실, 도구 실행 전 완료 보고, 기억 검토 중 필요한 읽기 도구 배제, 지침·목표의 조용한 잘림을 발견해 수정했다. 전체 단일 봉투·프로토콜·현재 requestId·DOM 구조 확인을 요구하고, 진행과 실제 완료를 분리한다. 앱 지침·목표·현재 원문은 온전히 보내며 선택적 검색 문맥만 공통 250,000자 전송 예산 안에서 줄인다. 준비 이후 권한·설정이 변경되면 이전 문맥을 버리고 다시 준비한다.

「세션과 기억처리」 원문 접근은 아직 확보하지 못했다. 실제 사용자 Work 로그인·모델 선택·삼성 실폰·24시간 실행은 확인하지 않았다. 표준 공개 GitHub Actions의 무료 KVM Android 검증을 준비했고 유료 실행기·artifact 저장·유료 API는 사용하지 않는다.

## 18시 13분 UTC — 첫 통합 검증과 남은 장기 운영 문제

Android debug 앱·instrumentation APK 빌드, 전체 JVM 단위 테스트와 lint를 함께 실행했다. 첫 통합 결과는 226개 중 220개 통과, 선택 실행 조건이 필요한 6개 건너뜀, 실패 0개였다. 실제 Android 기기에서 instrumentation을 실행한 결과와 구분한다. 최신 웹 전송은 Chromium 35개 사례를 통과했으며, 전송 버튼을 누르기 직전 현재 앱·OS 권한을 native에서 다시 확인하는 일회성 승인을 추가했다. 이후 Java 변경을 포함한 최신 스냅샷을 다시 검증한다.

실제 공개 ONNX 모델의 의미 검색과 키워드 검색을 결합한 별도 LongMemEval oracle 40문항 holdout에서 분수형 출처 Recall@20은 0.76625였다. 같은 문항의 native ANN 후보+원본 F32 재정렬도 같은 결과를 냈다. 공식 전체 benchmark 답변 정확도나 2년 사용 정확도는 아니다. 백만 원문 합성 자료에서도 보존과 검색을 측정했으며, 느린 검색·메타데이터 비용을 별도 기록하고 개선 중이다.

검토 중 두 장기 운영 문제가 추가로 확인됐다. ANN 전체 색인을 너무 자주 저장하면 큰 파일 쓰기가 반복되고, 마지막 저장 이후 새 기록만 추가돼도 재시작에서 전체 재구축할 수 있다. 변경 종류를 확인한 뒤 이전 체크포인트를 안전하게 이어 붙이는 경로와 쓰기 간격을 개선한다. 휴대폰 원문 spool은 이벤트마다 파일 하나를 보관해 백만 기록에서 백업 ZIP 엔트리 상한과 파일시스템 낭비에 도달할 수 있다. 원문 바이트와 해시를 보존하는 불변 구간 파일로 묶는 개선을 진행한다. 문제가 해결됐다고 미리 기록하지 않는다.

실제 독립 협업 모델 writer와 reader를 GPT-6.1 Sol/Medium으로 실행한 12개 합성 기억 사례의 출력도 확보했다. writer 인용 22개는 원문의 UTF-16 범위와 일치했다. 원문 일치는 의미 정확도와 다르므로 생성 메모·답변은 별도 rubric으로 검토한다. 이는 앱→Work 호출이나 삼성 실폰에서의 모델 실행을 검증한 결과가 아니다. 공개 저장 예정인 텍스트 파일 221개에 대한 지정 비밀 패턴 검사는 발견 0건이었다.

## 18시 33분 UTC — 실제 Android 가상기기 검증 확보

첫 기능 체크포인트 `bf96b72`를 GitHub에 저장했다. 첫 공개 KVM CI는 첨부 파일 보호 검증 후 테스트 정리 과정에서 dangling symlink를 놓치는 실패가 났다. 실제 원문 보호 assertion을 유지하고 순서가 다른 파일 삭제도 검증하도록 고친 `2b9403a`를 다시 실행했다. [무료 표준 실행기 CI](https://github.com/dog898996/be3hyu/actions/runs/38446332061)는 APK·전체 단위 테스트·lint·실제 native 패키징과 Android API 35 instrumentation을 모두 통과했다.

실제 Android 기본 검사 10개와 명시적 프로세스 강제 종료 후 재열기 검사 1개가 통과했다. 실제 앱의 ONNX 인코더는 공개 네 문장을 99ms에 처리했고 한국어·영어 cosine을 호스트 참조와 비교했다. 실제 JNI ANN은 256개 벡터의 저장·조회·손상 거부를 검증했다. 화면을 끈 65초 동안 foreground service가 실제 유지됨을 확인했다. [측정 원자료](benchmarks/android-ci-2b9403a.json)에 commit·run·job·조건을 남겼다. AOSP x86_64 가상기기 결과이며 S24 Ultra·실계정 Work·24시간 실행 측정이 아니다.

새 개선에서는 ANN이 마지막 체크포인트 뒤 순수 추가된 기록만 이어 붙이며, 가상 시계로 24시간·분당 8기록을 진행한 검사에서 11,521개 원문을 보존하고 전체 그래프는 초기 포함 5번 저장했다. 이것도 실제 폰을 24시간 켠 시험과 구분한다. 휴대폰 raw journal 구간 묶음과 교체 전 내부 검증, 100만 원문의 느린 FTS 경로, 많은 파생 메모의 의미 검색 비용, 새 사용자 입력의 도구 실행 보류와 명시적 중지 기능을 계속 검증한다. 새 기능은 위의 이전 commit CI 성공에 섞어 완료로 표시하지 않는다.

독립 모델 probe의 수동 rubric 검토는 reader 11개 통과·1개 부분 충족으로 판정했다. 외부 알림 명령의 미승인 상태 표현, 복합 메모의 일부 출처 누락, 날짜 연도의 추론 표시, 부분 원문의 추가 조회 필요 표현 같은 부족한 점을 공개 결과에 남겼다. 검색기 실행을 하지 않은 probe에 Recall이나 자동 답변 정확도 숫자를 만들지 않았다.


## 20시 52분 UTC — 장기 운영·입력 복구·알림 통합

미완료 목표가 일상적인 완료 보고 뒤에도 계속 쌓여 256개 한도에 도달할 수 있는 문제를 확인했다. 실제 관찰된 request-bound `completed` 보고와 알려진 폰·앱 실행 영수증을 대조한 뒤 운영 보관함으로 옮긴다. 이 보관은 전체 클라우드 성공의 독립 검증이 아니므로 `overallOutcomeVerified:false`를 유지한다. 단순 조회·기억 정리·위치 새로고침만 하는 자동 판단은 새 미완료 목표를 만들지 않는다. 평문 답변·status 누락·다른 요청에 연결된 봉투는 완료 보고로 인정하지 않으며 막힌 목표는 사용자 정리 없이 재개하지 않는다.

휴대폰 입력은 내용과 첨부를 한 원자적인 draft cohort로 보존하고, 보내기의 client input ID와 revision을 큐 저장·draft 소비와 함께 커밋하도록 연결했다. Activity가 입력 저장 후 사라져도 같은 ID의 재시도는 메시지와 실행을 중복 생성하지 않는다. A→B→A 같은 실제 수정은 별개 revision이므로 이전 보내기 결과가 새 입력을 지우지 않는다. 첨부 원본 저장 중 새 입력이 준비되면 이전 도구 제안은 보류하며, 준비 종료 뒤 최신 입력을 먼저 전달한다. 도구 영수증 claim과 새 입력 카운터를 같은 임계구역에서 결정해 확인과 실행 시작 사이의 경합도 닫았다. 이미 시작된 OS·클라우드 효과를 중지했다고 만들지는 않는다.

대화 미리보기는 별도 worker에서 40개·각 8,000자만 읽으며 이전 페이지와 전체 원문 읽기를 제공한다. 사진은 보이는 항목만 별도 worker·한정 bitmap 예산으로 처리한다. 실제 표시된 답장 원문 ID와 해시를 대조한 뒤에만 알림을 읽은 UI 상태로 기록한다. 실제 사용자 읽음은 추측하지 않는다. 알림 탭은 과거 원문 해시를 확인하고 해당 대화 페이지로 이동하며, 자기 답장 알림은 암묵적인 개인화 입력에서 제외한다.

백업은 기본 64GiB·설정 1~64GiB의 스트리밍 한도, private reserve 256MiB, 중간 공간 검사와 typed 오류를 추가했다. 커밋 전 실패 rollback과 커밋 후 정리 실패를 구분한다. 일반 작업 파일은 512MiB, 불변 대화 첨부 원본은 64MiB, 전체 텍스트 원문은 40MiB 바이트 한도로 분리했다. 외부 저장 제공자 여유 공간은 모를 수 있으며 실제 64GiB 폰 전송을 측정한 것은 아니다. 독립 실제 SQLite·파일·native bitmap 검사에서 새 storage/UI·폰 공간 검사를 합친 79개가 통과했고 draft helper 24개도 통과했다. 최종 전체 빌드·실제 Android 실행은 새 통합 스냅샷으로 다시 확인한다.

무료 실제 Android CI의 새 기능 검사에서 ONNX·JNI·raw journal 백업·원본 사진 viewer는 통과했지만 설정 저장 버튼의 실제 화면 터치가 실패했다. 키보드·keyguard·화면 wake 준비를 고친 뒤에도 이 한 사례가 남아 persisted 값과 화면 진단을 확보해 수정 중이다. 이 실패를 검증 통과로 숨기지 않는다. 추가 개발 토큰은 사용자가 직접 구매했고, 작업이 중단된 부분을 같은 소스에서 이어간다. 유료 API·호스팅·유료 CI 실행기를 추가하지 않는다.

모델 교체로 오래된 고정 이름이 전송을 막는 문제도 보완 중이다. 기본 GPT-6.1 Sol/Medium/Fast는 유지하고 사용자가 요구 모델·강도·속도를 UI나 대화로 변경할 수 있게 한다. 실제 선택값과 요구값을 대조하는 gate를 유지하며 더 약한 모델이나 유료 API로 자동 대체하지 않는다. 최신 DOM 전송·새 설정과 같은 소스의 최종 검증이 완료되면 별도 결과를 기록한다.

## 22시 38분 UTC — 대화·미디어·실행 경험과 재시작 통합

사용자는 사진·파일이 있는 대화, 긴 응답 대기, 폰 재시작·초기 로딩 충돌, 휴대폰 정보를 읽는 범위와 1년 이후 개인화를 전체 제품 흐름으로 다시 검증하라고 요청했다. [제품 흐름 기준](mobile-product-acceptance.md)에 구현과 실제 측정, 미검증 조건을 연결했다. 추가 비용을 발생시키는 서비스는 도입하지 않았다.

일반 대화에 최대 60,000자의 미검토 원문을 추가하던 경로를 제거하고 별도 기억 검토 12,000자 예산으로 분리했다. 필요한 검색과 원문은 유지한다. UI는 bounded 대화 페이지·별도 사진 worker·직접 첨부 메타데이터 조회·별도 파일 목록 worker를 사용한다. 로컬 준비량을 줄인 것과 실제 서비스의 첫 응답 속도를 측정한 것은 구분한다.

64MiB 사진 원본 보존과 별도 Work 전달 이미지를 연결했다. 실제 11MiB PNG를 유지하면서 예산에 맞춘 JPEG의 wire SHA·분석 범위를 native 계획, 실제 접수 관찰, 모델 분석과 연결하는 9개 통합 시험이 통과했다. 잘못된 SHA·파일명·원문 ID·삭제된 native 계획은 검토 완료로 인정하지 않는다. 전송 표현을 읽은 결과가 원본 전체 분석으로 승격되지 않는다. 영상·음성·PDF·ZIP·일반 바이너리의 native 바이트 보존과 Chromium File/DataTransfer를 별도로 확인했으며 모든 형식의 서비스 해석을 검증했다고 주장하지 않는다. 현재 전송 예산은 개당10MiB·합계20MiB·8개다.

기본 모델·강도·속도는 설정 및 대화로 바꾸되 실제 Work 선택과 일치하기 전에는 보내지 않는다. 브라우저 43개 검사가 통과했고, 실제 모델 선택이 업로드 중 바뀌면 승인·클릭 전에 차단했다. 이 검사는 실제 계정의 선택 메뉴·모델 생성·과금 telemetry를 확인한 시험이 아니다.

도구 영수증에 민감한 결과값·인자·예외 메시지를 제외한 작은 system 원문을 연결해, 유용한 실행 교훈을 정확한 출처로 기억할 수 있도록 했다. system 출처는 사용자 사실·선호로 승격되지 않는다. 실제 파일/SQLite를 쓰는 새8개와 읽기 실패5개, 총13개가 통과했다. 단순 조회 실패는 후속 요청을 계속하며 결과가 불명확한 쓰기는 자동 반복하지 않는다.

365개 가상 사용자 세션과 방해 기록30,660개를 누적한 실제 검색/출처 시뮬레이션은 24개 시나리오×4단계96개를 통과했다. 사람 손으로 만든 요약·별명·검토 답안이라는 한계를 공개했다. 첫날/365회차 선택문맥24개를 정답을 받지 않은 별도 협업 모델이 읽었고, 수동 rubric24개 충족·인용23개 정확히 문맥 존재를 확인했다. 실제 1년 자동 추출이나 전체 질문의100% 정확도, Dot 우위를 증명한 수치는 아니다.

초기 브라우저 로딩 중 renderer가 죽으면 영구 대기하던 문제와 main callback의 미처리 provider 예외를 고쳤다. 아직 문서가 로드되지 않은 실패는1→5→30→60초 간격으로 재시도하고, 이미 열린 문서·접수된 작업은 기존 결과 확인을 보존한다. 새 시작/복구12개도 전체 suite에서 통과했다. 단순 프로세스 crash·실제 재부팅·Android 강제 중지를 별도 단계로 검사하는 driver와 APK는 컴파일됐고 실제 KVM 실행은 다음 체크포인트에 수행한다.

최신 전체 생산/unit 소스와 debug·AndroidTest APK가 컴파일됐다. 전체494개 중477개 통과·16개 명시적 조건부 건너뜀·1개 실패였다. 실패는 첨부 분석의 초기 접수가 아니라 백업 복원 뒤 검토 상태였고, 시험의 accepted/inflight provider를 완료된 분석으로 가정한 경계였다. 복원에서 실제 미완료 요청을 uncertain으로 격리하는 정책을 유지하며 settled/미완료 복원의 서로 다른 기대를 검증하고 있다. 이 단계에서 lint·최종 배포 성공을 미리 기록하지 않는다.

공식 Space/Library 원문 접근을22:33UTC에 다시 확인했으나 「세션과 기억처리」 본문은 여전히 확보하지 못했다. 새 공개 텍스트291개 지정 비밀 패턴 검사에서 발견0건이었고 값은 출력하지 않았다. 기존 release 개인키는 공개 Git 밖에서 보존하고, 장기 업데이트를 위한 별도의 비공개 서명키 백업을 실제 byte round-trip으로 확인했다. 이 비공개 파일은 공개 repo·release에 포함하지 않는다.

## 22시 44분 UTC — 최종 로컬 체크포인트

첨부 분석이 끝난 시험은 실제 Runtime처럼 provider 상태를 completed로 정리하고, 미완료 accepted의 백업은 uncertain/재검토로 복원되는 반대 시험을 추가했다. 원문·분석·두 SHA를 보존하며 proof 조건이나 assertion을 낮추지 않았다. 또 실행 경험·목표 보관의 내부 system JSON이 대화방을 채우던 실제 UI 연결 문제를 수정했다. 원문·검색·백업은 그대로 두고 보이는 대화 페이지와 가벼운 갱신 확인만 구분한다. 평문 한도·오류 안내와 사용자 JSON 메시지는 계속 표시한다. 파일을 8개 넘게 선택하거나 가져오기 중 선택이 바뀐 경우 일부만 조용히 추가하지 않고 이유와 보관 여부를 표시한다.

최신 Coordinator44개·bounded 대화10개, 총54개가 실패·건너뜀 없이 통과했다. 최신 생산 코드·debug APK·AndroidTest APK 컴파일과 lint가 통과했고 lint는 오류0·warning16개다. binary 권한40개가 소스와 일치하고 실제 ONNX/JNI 양 ABI의16KiB 패키징을 검사했다. 앞선 전체494개 기록과 이 수정 이후 targeted54개를 중복 합산하지 않는다. 같은 커밋의 무료 실제 Android CI와 안정적인 개인키 release 빌드에서 최신 전체 suite를 다시 확정한다. [체크포인트와 현재 소스 SHA](benchmarks/mobile-local-checkpoint-2026-10-13.json)를 공개한다.

## 23시 44분 UTC — 원문 RFC 확보·복구 결함·5년 기준선

사용자가 「세션과 기억처리」 원문을 파일로 제공했다. 1,034행·99,691바이트 전체를 읽고 SHA-256 `4b778bdb7d71abc838bafcffa05bf83c2b105ad4e2837ce620cb32857ef21194`로 고정했다. 이전 Library 접근 실패는 당시 기록이며 현재 원문 검토는 완료됐다. [항목별 적용 계획](memory-rfc-integration-plan.md)에 기존 Android/Work 구조와 RFC의 차이, 다섯 계층 필수 조회·전달 패킷 해시·정정/삭제 fence·자율 판단·검증 범위를 기록했다. 적용 계획은 구현 완료를 의미하지 않는다.

실제 private 파일/SQLite 검증에서 Store 초기화가 복원 저널보다 먼저 실행되면 빈 originals 경로를 만들고 유일한 이전 원문 세대를 삭제할 수 있음을 재현했다. 복원 검사부터 초기화하고, 실패 시 원문·저널을 보존하며 읽기 전용 복구 화면과 worker 재시도를 제공한다. 차단 상태의 파일 변경도 거절한다. 저장소 회귀41개와 실제 Application/서비스 경계8개가 통과했다. 동결 소스의 전체526개는510통과·16개 명시적 opt-in 건너뜀·실패/오류0, lint 오류0·경고16이었다. debug/AndroidTest APK 컴파일도 완료했다. 이전 실제 Android CI는 Quickstep 시스템 ANR와 instrumentation 종료가 대상 앱을 force-stop하는 fixture 영향으로 실패했고, 실제 assertion을 유지한 수정으로 새 CI를 수행한다.

마지막 합격 기준은 5년보다 오래된 첫해 기록 회상으로 강화했다. 결과를 보기 전에 최종 시점2026-12-31·첫해2021·2,191일·방해 기록184,044개·고정144질문으로 preregistration v2를 수정했다. 동일한 생산 검색기의 실제 기준선은 원문 전달130/144, 원문만 저장한 상세 질문10/12였다. 별명 다단계 연결12개와 식별번호2개를 놓쳤고 삭제 요청 뒤 노출6건이 있었다. [기준선 전체 결과](five-year-memory-baseline-results.md)를 공개하며 불합격으로 기록한다. 모델 답변 정확도, 개선 버전, 실제 Work 서비스와 실폰 장기 실행은 이 수치에서 측정되지 않았다. 추가 유료 API·호스팅을 사용하지 않았다.
