# 호영 0.4.7 — 열린 Work 선택창 감지 수정

0.4.6을 설치한 사용자 기기에서도 자동 선택이 중단됐다. 받은 진단은 로그인·Work·6.1 Sol·Medium을 확인했지만 `triggerCount=1`, `menuCount=0`, `sliderCount=0`, `fastControlCount=0`, `selectionClicks=1`이었다. 선택창을 연 뒤 연결된 팝업을 놓치는 경로가 남아 있었다. 입력 영역에서는 229자가 감지됐으며, 실제 초안인지 UI 외곽 문구인지는 이 진단만으로 확정할 수 없다. 전체 사용자 진단이나 개인 정보는 저장소에 저장하지 않는다.

## 변경

- 버튼의 `aria-controls`·`aria-owns`가 가리키는 요소를 직접 찾는다. 연결 대상이 `menu`·`dialog` 역할이 없는 일반 컨테이너, `group`, `display:contents` 외곽이어도 읽는다. 연결 속성이 없는 알려진 모바일 형태는 현재 모델 헤더와 슬라이더가 함께 있는 범위로 확인한다. 무관한 메뉴나 복수 팝업을 임의 선택하지 않는다.
- 선택창을 열면서 버튼 표시가 ‘GPT-6.1 Sol Medium’에서 ‘추론 수준 선택’으로 바뀌어도 같은 버튼의 연결을 유지한다. 팝업이 바깥 화면을 접근성 트리에서 가리는 경우에도 앞서 확인한 Work와 해당 버튼을 추적한다.
- `prompt-textarea` ID가 입력창 외곽에 붙는 형태에서는 내부의 실제 편집 요소를 찾는다. 주변 안내는 초안으로 읽지 않고, 사용자가 작성한 실제 초안은 보존한다.
- 앱이 연 선택창의 유한한 진입·닫기 애니메이션만 완료해, 백그라운드 WebView에서 정지된 애니메이션이 선택 확인과 입력 포커스 해제를 막지 않게 한다. 닫기 표시만 바뀌고 포커스 영역이 남아 있는 경우도 처리한다.
- **연결 진단 복사**는 이전 오류 기록과 별도로 현재 문서의 읽기 전용 스냅샷을 얻는다. 입력창의 종류, 연결된 팝업 구조, 모델 제어 표시를 포함하며 대화·초안 본문·비밀번호·쿠키·토큰·전체 DOM은 수집하지 않는다. 이 작업은 모델 설정을 바꾸거나 요청을 보내지 않는다. 응답이 없으면 2초 뒤 미확인으로 명시한다.

기존 앱 위에 업데이트한 뒤 **Work → 연결**을 누른다. 선택창을 직접 열어둘 필요는 없다. 실제 웹 초안이 있으면 그 내용을 지우지 않고 초안 상태를 표시한다. 앱의 대기 메시지·장기기억·권한·백업 형식은 변경하지 않는다.

## 검사 범위

수정 전 재현 검사에서 버튼 표시 변경, 역할 없는 연결 팝업, 입력창 외곽 문구, 정지된 진입 애니메이션 네 경로가 실패하는 것을 확인했다. 수정 후 해당 경로와 모바일 팝업 가림·닫기·전송 접수, 모호한 팝업 거부, 진단 본문 제외를 검사한다. 기존 연결·첨부·응답 수집·중복 전송 방지 경로와 네이티브의 현재 화면 진단·기존 작업 보존도 확인한다.

브라우저 연결 회귀 검사 **84/84**, 네이티브 관련 검사 **5/5**를 통과했다. 마지막 텍스트 콜백 인자 정리 후에는 영향 범위인 모바일 선택창·Fast 검사 **14/14**를 다시 통과했다. 네이티브 진단은 현재 문서만 읽고 타임아웃 뒤 늦게 온 응답으로 결과를 두 번 반환하지 않는 것까지 검사했다. 서명 릴리스 빌드·필수 lint·APK 검사와 패키징된 연결 스크립트 6개 파일의 원본 일치 확인도 통과했다.

실제 Galaxy의 DOM은 이 환경에서 직접 접근할 수 없으므로, 재현 검사 통과를 사용자 기기의 연결 성공으로 보고하지 않는다. 이 수정은 코드에서 재현한 감지 결함을 해결하며, 사용자 화면에서 발생한 모든 세부 DOM 차이를 확정했다는 의미는 아니다. 유료 모델 호출과 전체 장기기억 시뮬레이션은 수행하지 않는다.
