# 호영 0.4.10 — Work 답변 회수와 연결 재시도

Work 웹에는 답변이 나왔지만 앱에는 도착하지 않는 경로와 연결 버튼을 눌러도 재시도가 진행되지 않는 경로를 수정했다. 설정의 사용량 절약 탭과 중복 목표 입력도 정리했다.

## 변경

- 접힌 사용자 메시지의 ‘더 보기’·복사 버튼을 본문 비교에서 제외한다. 작성한 전체 본문은 정확히 대조해 첫 전송 후 대화 주소를 인계한다.
- 새 CodeMirror 형식의 `hoyoung` 코드블록에서 완성된 JSON 원문을 읽는다. 코드 일부가 가상화돼 빠진 상태는 완성된 응답으로 취급하지 않는다.
- 같은 대화의 프로젝트 주소, 메뉴 열림, 다른 대화로 갔다 돌아오는 상황을 구분한다. 같은 사이트의 주소 변화로 브리지를 영구 종료하지 않는다.
- 연결이 끊긴 요청과 정확히 일치하는 기존 답변은 ‘연결’에서 읽어 앱으로 회수한다. 같은 메시지를 재전송하지 않으며 복구한 결과임을 표시한다. 원문은 저장하고, 기존 실행 문맥을 잃은 작업·기억 변경 제안은 재실행·승격하지 않는다. 정정·삭제 상태가 바뀐 옛 답변은 자동으로 대화에 공개하지 않는다.
- 페이지 로딩 실패 후 ‘이미 시작됨’ 상태 때문에 재시도가 무시되던 경로를 고쳤다. 30초 동안 로딩이 끝나지 않으면 재시도 가능한 상태로 전환한다. 버튼을 연타해도 같은 페이지를 중복 새로고침하지 않는다.
- 웹 렌더러가 교체되면 현재 Work 화면에 다시 붙인다. 앱 내부 실행 중인 요청의 모델은 변경하지 않는다.
- 사용량 절약 탭·수동 사용량 입력·별도 ‘계속 맡길 일’ 입력칸을 제거했다. 저장된 목표·기억과 절약 정책은 보존하며 채팅의 최신 지침을 설정 저장으로 덮어쓰지 않는다.
- 설정의 `64`에는 ‘백업 용량 한도 · GiB’와 설명을 붙였다. 기본 64 GiB는 한 번의 백업·복원에서 아카이브와 풀린 내용에 적용하는 상한이며, 미리 확보하는 공간·현재 사용량·기억 개수가 아니다. 실제 여유 공간 확인도 별도로 유지한다.

## 업데이트와 기존 요청 복구

기존 앱 위에 업데이트한 뒤 Work에서 ‘연결’을 누른다. 이전 버전이 첫 대화 주소를 저장하지 못한 경우에는 웹의 대화 목록에서 **답변이 나온 이전 호영 대화를 한 번 열고 → 연결**을 누르면 된다. 이미 보낸 요청을 다시 보내거나 앱 데이터를 지울 필요가 없다. 다른 사람의 대화나 임의 결과를 같은 요청으로 취급하지 않는다.

복구한 답변에 도구 실행·기억 변경 제안이 포함돼 있으면 원문에 보관한 뒤 남은 작업은 새 지시로 이어간다. 아직 진행 중이거나 불완전한 답변, 요청 식별자가 없는 답변을 완료로 꾸미지 않는다.

## 검증 범위

브라우저 연결 검사 **95/95**, Android 로컬 검사 **37/37** 통과. 공개 캡처 HTML과 보고된 한국어 UI 구조로 접수 실패·새 코드블록 실패를 재현했고, 재시도·연속 입력·복구 후 후속 요청·버튼 연타·화면 교체·설정 충돌을 확인했다. 유료 모델 호출과 장기기억 전체 시뮬레이션은 반복하지 않았다.

실제 Galaxy와 로그인된 제공자 계정의 최종 실행은 이 환경에서 직접 확인하지 못했다. 이 기록은 로컬 재현과 코드 검증 결과이며 모든 외부 UI 변화에 대한 무결함 보장이 아니다.
