# 호영 0.4.4 — 일반 Work 연결과 연속 지시 처리

호영 앱·장기기억·휴대폰 도구를 유지하고 **일반 Work 대화**로 연결한다. 임시 채팅 버튼을 요구하지 않는다. [설치 파일](https://github.com/dog898996/be3hyu/releases/tag/v0.4.4).

## 연결과 세션 교체

- Chat On Steroids 2.1.37의 DOM 연결 모듈을 MIT 조건으로 가져왔다. 입력창·전송·중지 버튼과 생성 중 상태를 읽으며, Android의 요청 큐·첨부·원문 저장·폰 도구 실행기는 계속 사용한다. 원본 커밋과 SHA-256은 [고정 소스 정보](../mobile/app/src/main/assets/vendor/chat-on-steroids/source.json)에 있다. 데스크톱 앱, MCP 서버·터널, React 내부 판독기는 포함하지 않는다.
- 일반 Work의 첫 전송 뒤 `/`에서 `/c/대화ID`로 바뀌어도, 앱이 보낸 원문과 새 사용자 턴이 일치할 때 같은 작업으로 추적한다. 기록한 앱 대화는 프로세스 재시작 시 같은 주소로 연다.
- **새 Work 대화**를 누르면 앱이 직접 만든 이전 대화만 삭제하고 새 대화를 연다. 화면 이탈이나 추가 메시지는 세션 교체가 아니며 진행 중 작업을 끊지 않는다.
- 삭제 버튼 클릭만으로 성공이라고 하지 않는다. 정확한 대화 ID, 삭제 확인 창, 제공자의 삭제 완료 표시를 확인한다. 확인이 끊기거나 UI 구조가 다르면 새 전송을 보류하고 **삭제 확인 복구**로 직접 확인할 수 있다. 이때 폰에 저장한 기억·설정은 지우지 않는다.
- 대화 ID·삭제 진행 영수증은 앱의 `noBackupFilesDir/work-conversation.json`에 원자적으로 기록한다. 오래된 백업에서 삭제 권한을 되살리지 않도록 이 실행 영수증은 개인 기억 백업과 분리한다. 앱 삭제·데이터 삭제로 영수증이 사라지면 이전 웹 대화는 자동 삭제 대상으로 추정하지 않는다.
- 활성 대화는 ChatGPT 기록에 표시될 수 있다. 세션 교체 전 삭제 방식이지, 처음부터 기록이 생기지 않는 임시 채팅 방식이 아니다. 대화 삭제는 계정의 별도 저장 메모리를 삭제하는 동작도 아니다.

## 기억의 기준

매 요청에 `APP_MEMORY_AUTHORITY`를 넣어 현재 앱 지침·프로필·출처가 검증된 기억을 개인화 근거로 사용하도록 한다. 계정의 저장 메모리·맞춤 지침·다른 대화의 개인 정보는 근거로 사용하지 않으며, 앱의 최신 정정·삭제·제외 정책이 과거 정보보다 우선한다. 앱 근거가 없으면 기억 검색 또는 모른다는 답을 요구한다.

**이 프롬프트가 ChatGPT 계정 메모리 기능 자체를 끄지는 않는다.** 이번 검사는 실제 모델에 상충하는 계정 기억을 주입해 답변을 채점한 검사가 아니다. 로컬에서 최종 전송 프롬프트에 현재 이름·지침·정정 원문이 포함되고, 제외한 원문이 과거 기억을 통해 재진입하지 않는지를 확인했다. 실계정에서의 혼용 0%를 보증하지 않는다.

## 처리 중 연속 메시지

- 새 메시지는 계속 입력할 수 있고 원문과 첨부를 먼저 보관한다. 대화 상단에 추가 지시 대기 수를 표시한다.
- 마지막 메시지뿐 아니라 원 요청 이후 중간에 보낸 수정·취소·추가 지시도 `ORDERED_OWNER_UPDATES`로 시간순 제공한다. 중간 취소 뒤의 잡담 때문에 취소가 사라지지 않는다. 삭제·제외된 중간 원문은 포함하지 않는다.
- 이미 전송한 요청의 결과가 돌아왔을 때 새 지시가 있으면 과거 계획의 아직 실행하지 않은 폰 동작·기억 반영을 보류하고, 새 입력을 우선 처리한 뒤 원 작업을 재검토한다. 별도 작업을 다른 요청 ID에서 중복 실행하지 않도록 지시한다. 진행 중 작업과 후속 처리의 모델 선택은 유지한다.
- Web Work의 실행 중 모델 응답에 즉시 입력을 주입하는 기능은 확인되지 않았다. 현재 연결은 **추가 입력 보관 → 기존 결과 보존 → 최신 지시 대조 → 후속 동작 반영** 방식이다. 이미 수행한 클라우드 동작을 소급 취소하거나 즉시 중단했다고 표시하지 않는다.
- 필수 지시가 문맥 한도를 넘으면 중간 지시를 몰래 버리지 않고 전송을 보류한다. 매번 전체 과거 대화나 장기기억을 추가하는 방식은 아니다.

## 설치 후 연결

1. 기존 앱 위에 0.4.4 APK를 업데이트한다. 기존 개인 설정·계정·장기기억 백업 형식을 바꾸지 않는다.
2. 사이드바 **Work**에서 로그인하고 **Work 선택 → 연결 확인**을 누른다. 임시 채팅을 켤 필요가 없다.
3. 모델은 6 Sol / 6.1 Sol / Astra 중 선택하며 Fast 토글도 유지된다. 실제 웹 선택 확인이 되어야 요청을 보낸다.
4. 세션을 바꾸려면 작업 결과 저장이 끝난 뒤 **새 Work 대화**를 누른다. 삭제 자동 확인이 실패하면 해당 대화를 웹에서 직접 삭제하고 **삭제 확인 복구**를 사용한다.

관련 네이티브 **14/14**, 브라우저 연결 fixture **66/66**, 서명 릴리스 빌드와 릴리스 필수 lint를 통과했다. APK의 기존 서명·48개 권한·네이티브 라이브러리 및 포함한 연결 스크립트도 확인했다. 검사 결과는 [집중 검사 기록](benchmarks/android-v044-focused.json), [APK 검사 기록](benchmarks/android-v044-apk.json)에 남긴다. 전체 5년 시뮬레이션·전체 Android 제품 검사는 반복하지 않았다. 유료 모델 호출이나 계정 설정 변경은 하지 않았다. 실제 로그인한 휴대폰 Work 연결·삭제·계정 기억 혼용은 이 환경에서 검증하지 못했다.
