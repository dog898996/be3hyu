# 호영이 장기 기억 연구와 구현 판단

검토일: 2026-10-13. 목표는 1~2년 원문을 삭제하지 않고, 오래된 근거도 회수하며, 현재 상태와 과거 상태·추론을 섞지 않는 개인 기억이다. 저장, 검색, 답변 정확도는 별도 문제로 평가한다. 사용자가 지정한 Space/Library 기억 설계 파일 본문은 아직 확보하지 못했으므로 이 문서는 그 파일을 읽었다고 주장하지 않는다.

## 구현 결론

1. **원문은 삭제하지 않는다.** 메시지·장치 관찰·첨부 원본을 내부 영속 저장에 보관한다. 파생 인덱스와 벡터는 재생성 가능하며 원문을 대체하지 않는다. 앱 제거·데이터 삭제·기기 분실은 별도 백업 없이는 복구할 수 없다.
2. **전체 저장소에서 후보를 고른다.** 최근 200개를 먼저 자른 뒤 검색하는 방식을 피한다. FTS/정확한 문자열/별칭/기간 조건으로 전체 집합을 조회하고 점수를 계산한 후 후보를 제한한다. 후보 제한에 걸렸으면 결과에 공개한다.
3. **중요 프로필은 별도로 pin한다.** 현재 유효한 선호·제약·목표를 최근성 검색과 무관하게 작은 영역에 넣는다. pin 자체가 사실 검증은 아니며 출처·현재 유효성·충돌을 표시한다.
4. **정확 검색과 의미 검색을 조합한다.** 별칭·개념 확장은 명시적 보조 기능이다. 실제 신경망 검색은 로컬 다국어 인코더의 준비 상태와 모델 버전을 표시하며, 준비되지 않은 상태를 신경망 검색으로 가장하지 않는다. 개인 데이터를 새 임베딩 API로 보내지 않는다.
5. **사실 시점을 분리한다.** 기록된 날짜와 사실이 유효한 날짜를 구분한다. 바뀐 값은 이전 버전을 남기고, 같은 기간에 충돌하는 값은 양쪽 근거를 제공한다. 새로 들어왔다는 이유만으로 참이라고 판정하지 않는다.
6. **근거가 들어 있는 구간을 보낸다.** 큰 원문 첫 부분만 잘라 넣지 않는다. 검색 일치 구간과 필요한 인접 발화를 가져오고 원문 ID·오프셋·해시를 남긴다. 예산 때문에 빠진 근거는 추가 원문 조회로 이어갈 수 있어야 한다.
7. **반복은 검증이 아니다.** 같은 원문에서 만든 메모가 여러 개라고 독립 근거가 늘지는 않는다. 검색 횟수는 사실 확신을 올리지 않으며, assistant 생성 주장과 사용자의 직접 진술·장치 관찰은 구분한다.

## 측정 계획과 주장 한계

별도 장기 검색 회귀에는 730일 범위의 합성 기록, 오래된 희귀 사실, 200개 이상 최신 방해 메모, 문장 내 뒤쪽 근거, 다중 세션 결합, 현재/과거 변경, 동시에 충돌하는 값, 별칭·다국어 표현, 근거가 없는 질문, 컨텍스트 예산 압박을 포함한다. 측정은 원문/메모의 Recall@K, 근거 ID 회수, 변경·충돌 표시, pin 회수, 예산 안의 근거 보존, 벡터 캐시 무효화와 검색 지연을 분리한다.

합성 자료의 검색 통과는 GPT 답변 정확도, 사용자 2년 실사용 정확도, 한국어 개인화 완성도 측정이 아니다. 실제 Work 모델의 추출·답변·판정은 아직 측정하지 않았으며 공개 벤치마크 reader/judge API를 몰래 실행하지 않는다. 파일이 남는다는 주장과 모든 질문에서 올바른 근거를 찾는다는 주장도 구분한다. 원문·사진·수정 이력·벡터를 함께 보관하므로 “1년 전체 기록이 20MB” 같은 고정 용량 약속은 하지 않는다.

## 무료 모바일 적용의 범위

기본 검색·출처 관리·기간/별칭 처리·원문 보존은 SQLite와 Java로 오프라인 실행한다. 신경망 의미 검색은 공개 다국어 가중치와 Android 로컬 추론을 사용하고, 설치 여부·인덱싱 진행률을 표시한다. 인덱스가 비어 있거나 일부 원문만 처리됐다면 그 범위를 감추지 않고 정확 검색을 병행한다. 모델 가중치·캐시 저장 공간과 배터리 사용은 실제 장치에서 측정해야 한다. Graphiti/Letta/mem0의 서버나 유료 기본 API를 설치하는 방식으로 비용 0원 조건을 충족했다고 표현하지 않는다.

## 현재 검색 구현과 대량 처리 한계

`MemoryRetriever`는 전체 FTS 집합의 정확 검색, 명시적 개념/별칭 확장, 독립 pin, 로컬 신경망 후보를 조합한다. 원문은 FTS 일치 구간 또는 해시로 검증한 실제 UTF-16 범위를 반환한다. 오래된 as-of 질문은 최신 20개 수정본만 읽는 대신 전체 수정 메타데이터를 검사하고 해당 기간의 버전을 우선 회수한다. 시간 범위를 지정한 원문 검색은 기록/관찰 시점 조건이며 사실의 유효 기간 조건과 다르다.

벡터는 현재 원문/메모 해시와 모델 ID가 일치할 때만 사용하며 백업의 권위 있는 자료에 포함하지 않는다. 전체 원문은 tokenizer가 허용하는 구간과 작은 겹침으로 점진 색인한다. 진행률은 완료한 출처 수와 처리한 UTF-16 문자 수로 표시한다. 캐시 준비율이 높아도 검색 결과나 사실 정확도가 보장되는 것은 아니다. 기기 출처의 현재 앱/OS 읽기 권한이 제한되면 원문과 이를 포함한 혼합 파생 메모를 검색 결과에서 제외하고 원본 기록은 유지한다.

초기 캐시는 정확한 float32이다. 512차원 구간당 벡터 자체만 2,048바이트이므로 100만 구간은 약 2GB이며 SQLite 인덱스·본문·모델 가중치는 별도다. 검색은 128개씩 페이지를 읽고 Store 잠금 밖에서 cosine을 계산한다. 각 신경망 인덱스 검색에는 1,500ms 예산을 두며 다 읽지 못했으면 `semanticScan.limitReached`로 공개한다. 읽은 벡터 수·바이트·시간도 반환한다. 대형 원문 하나가 후보를 독점하지 않도록 검색 중 출처별 두 구간 제한을 적용한다. 이 방법은 ANN이 아니며 대량 구간에서 의미 검색 Recall이 떨어질 수 있다. 전체집합 정확 검색은 별도로 유지한다.

현재 원문 구간은 준비된 ANN shortlist를 float32로 다시 정렬할 수 있다. **추출한 요약 메모의 벡터는 별도 문제**다. 기존 방식은 원문 ANN 전에 요약 벡터를 매번 최대1.5초 훑었다. 현재 cache가4096행/512차원 기준약8MiB를 넘으면 전부 훑지 않고, 기존 키워드 후보 일부와 검증된 원문 source에 연결된 메모를 최대256개 고른 뒤 현재 revision/hash/권한을 확인하고 float32로 정렬한다. 작은 cache는 기존 전체 페이지 검색을 유지한다. 원문 ANN·전체집합 키워드 검색·프로필·수정 이력을 버리지 않는다. 진단용 원문 `UNION` 전체 materialization도 없애고 실제 progress에서 원본 PK를 조회한다. 전체 문자 합계·현재 cache 개수 계산에는 아직 선형 비용이 남아 있으므로100만 기록 전체 검색의 새 속도를 이 변경만으로 주장하지 않는다.

이 변경은 **전체 요약 메모의 신경망 검색이 아니다**. 원문 후보에 연결되지 않거나 shortlist에서 잘린 메모는 빠질 수 있다. source 연결은 전체 원문 ID 단위이며 정확한 quote 구간별 관계 인덱스는 아니다. 한 원문에 많은 메모가 있으면 저장 인덱스 순서로 먼저 후보를 제한한다. `structuredMemorySemantic.wholeCorpusMemoryNeuralSearch=false`, candidate cap, 실제 읽은 벡터/바이트를 반환하고 prompt에도 제한을 표시한다. 관련 원문을 정확히 찾았다고 연결된 모든 요약을 찾은 것으로 부풀리지 않는다.

프로필 pin도 무한하지 않다. 후보 최대1000개 중 별도 예약12개이며, 후보 모집단·잘림·예약 포화를 diagnostics와 prompt에 표시한다. 최종 문맥 예산 때문에 예약된 메모도 모두 들어가지 않을 수 있다. bounded sourceRefs128개 뒤에 권한 취소된 폰 원본이 있어도 전체 normalized 관계를 확인해 현재·역사 메모의 본문을 차단한다. 화면의 `sourceCount`는128개 view 길이 대신 실제 원본 관계 수를 표시한다.

대안은 float16/int8 벡터, 계층별 후보 추림, HNSW 등 ANN이다. 각각 저장/CPU를 줄이지만 정밀도·희귀 근거 회수 손실이나 Android 네이티브 의존성이 생긴다. 실제 선택한 가중치의 float32 기준과 비교하기 전에는 효과·정확도를 보장하지 않는다. 특히 긴 원문 평균 벡터로 출처를 먼저 자르면 한 번 언급한 희귀 사실이 희석될 수 있다.

`LargeCorpusRetrievalBenchmarkTest`는 `HOYOUNG_MEMORY_SCALE=100000`으로 별도 실행하는 실제 Store/Retriever 성능 시험이며 100만 원문도 같은 방식으로 지정할 수 있다. 작은/큰 집합의 오래된 정확 근거, 한국어 별칭, 개체 다중 근거, 시점과 충돌, 없는 근거를 비교하고 DB+WAL 바이트·검색 시간·캐시 상태를 출력한다. 정답 메모·별칭을 수동으로 넣으므로 추출 품질 시험이 아니다. Robolectric/JVM 시간은 Galaxy S24 Ultra의 측정값도 아니다. 실제로 실행해 확보한 결과만 완료된 측정으로 보고한다.

별도 `PublicDatasetRetrievalBenchmarkTest`는 [공식 cleaned LongMemEval 데이터 카드](https://huggingface.co/datasets/xiaowu0162/longmemeval-cleaned)의 MIT 표기를 확인하고 oracle 파일 revision `98d7416`을 사용한다. 다운로드된 파일 SHA-256은 `821a2034d219ab45846873dd14c14f12cfe7776e73527a483f9dac095d38620c`이다. 질문 유형별 round-robin으로 40개와 다음 40개를 선정하고, 2,131개의 동일 출처 발화 집합에서 annotated `has_answer`와 `answer_session_ids`로 정답 원문 ID를 구한다. 정답 답변이나 수동 정답 메모를 검색에 넣지 않는다. 다른 사례의 발화를 방해 자료로 섞으므로 표준 LongMemEval S/M 실험과 다르며 표준 점수라고 보고하지 않는다. 원본·시험 fixture는 개발 환경의 `/tmp`에만 있고 앱에는 포함하지 않는다. 준비 스크립트와 opt-in 시험은 저장소에 남긴다. 무응답 질문은 이 공개 근거-ID 평가에 포함하지 않았으므로 LLM의 무응답 정확도를 측정했다고 주장하지 않는다.

LoCoMo의 [실제 LICENSE.txt](https://github.com/snap-research/locomo/blob/main/LICENSE.txt)는 CC-BY-NC-4.0이다. 공개 파일이라는 이유만으로 무제한 상업 배포 허가로 취급하지 않는다. LongMemEval의 코드 MIT와 데이터 카드 MIT도 별도로 확인했다.

Android tokenizer/ONNX 실행의 수치 일치와 폰 추론 시간은 별도 검증 대상이다.

원문 근거 목록은 이제 출처 ID 단위로 합치고 키워드·의미·메모 링크의 순위를 RRF로 합산한다. 정확한 식별자에는 별도 보너스를 둔다. cosine과 SQL 점수의 숫자 크기를 그대로 비교하지 않는다. 이 개선은 검증한 자료의 평균 근거 회수를 높였지만, **완전 기억이나 정확한 답변을 보장하지 않는다.** 대량 캐시의 ANN 대안은 별도 모듈과 측정으로 검토한다. ANN은 검증된 float32 SQLite 파생 캐시를 참조하며, 기억의 권위 있는 자료는 원문과 출처·수정 이력이다. float32와 ANN 캐시는 원문에서 재생성할 수 있다.
