# 화면 임시 선택, 영구 라우팅, 비서 프로필

0.4.3 업데이트: 모델 선택 UI는 6 Sol / 6.1 Sol / Astra 세 가지다. Fast는 켜고 끌 수 있으며 끄면 Standard다. 아래 표의 Fast는 초기 기본값을 설명하며, 임시·영구 속도 선택은 모델·강도와 함께 고정해 같은 작업의 후속 처리까지 보존한다. [최신 변경](release-v043.md).

0.4.1에서는 **다음 메시지의 화면 선택**과 **이미 접수한 작업의 선택**을 분리한다. 화면을 나갔다는 이유로 실행 중인 Work의 모델을 바꾸거나 취소하지 않는다.

| 상황 | 새 메시지 | 이미 접수한 작업 | 5분 정기 판단 |
|---|---|---|---|
| 처음 열기 | 영구 설정, 기본 Medium + Fast | 저장된 작업 설정 | 기본 Medium + Standard |
| 보내기 옆에서 XHigh 선택 | 이후 메시지도 XHigh + Fast | 기존 선택 유지 | 변경 없음 |
| 채팅으로 ‘이번 작업 XHigh’ | 변경 도구 성공 뒤 XHigh + Fast | 해당 요청의 다음 호출부터 XHigh | 변경 없음 |
| 같은 앱에서 탭 이동·화면 회전 | 임시 선택 유지 | 변경 없음 | 변경 없음 |
| 홈·다른 앱·외부 파일 선택 화면·화면 꺼짐 | 다음 입력부터 영구 설정 | 선택과 후속 호출 유지 | 변경 없음 |
| 프로세스 종료 후 다시 열기 | 영구 설정 | 저장된 선택 유지, 기존 작업 복구 규칙 적용 | 영구 설정 |
| 설정 또는 채팅으로 영구 값 변경 | 저장된 새 기본값 | 접수된 명시적 임시 선택 유지 | 해당 영구 항목을 변경한 경우 반영 |

추론 강도 Ultra와 속도 UltraFast는 별개다. 속도에는 Fast/Standard만 사용하며 UltraFast를 요청하지 않는다. 실제 Work에서 모델·강도·속도가 확인된 뒤 전송한다. Fast는 즉각적인 답변 완료를 보장하지 않는다.

## 전송·설정 충돌 처리

- 보내기를 누른 순간 임시 선택을 캡처한다. 첨부 파일 저장 중 화면을 꺼도 그 요청은 캡처한 값을 쓴다.
- `ForegroundRoutingSession`은 메모리에서만 관리한다. root request의 `ownerRouteOverride`는 SQLite에 보관한다. 후속 처리·재시도도 동일한 root를 사용한다.
- 앱 이탈은 foreground 선택만 비운다. 진행 중 Work 취소나 모델 선택 재설정을 호출하지 않는다.
- 화면 session ID와 revision이 달라졌으면 늦게 도착한 채팅 설정 명령·열어둔 선택 창은 최신 선택을 덮어쓰지 않는다. 실패한 임시 변경을 영구 변경으로 대체하지 않는다.
- 채팅으로 모델 변경과 작업을 동시에 요청한 턴은 모델 변경 도구만 실행하고, 실제 폰 작업은 선택된 모델의 후속 턴으로 넘긴다.
- 영구 설정 UI는 실제로 편집한 필드만 저장한다. 열었을 때의 원래 값과 저장 직전 값을 비교해 같은 항목의 충돌을 거부하고 다른 항목의 최신 변경은 보존한다.
- UI와 채팅은 같은 설정 검증·저장 경로를 사용한다. 채팅의 이전 설정 revision도 확인한다. 현재 설정을 다시 읽고 의도적으로 변경할 수 있다.
- 기존 Low 정기 판단 기본값은 한 번만 Medium으로 이행한다. 기존 High 이상과 이행 이후 직접 선택한 Low는 덮어쓰지 않는다.

## 이름과 프사

설치 기본값은 호영과 사용자가 지정한 고양이 사진이다. 설정의 ‘프로필과 이름’ 및 `app.identity.update`로 수정한다. 새 프사는 첨부 또는 작업 파일의 ID를 사용한다.

현재 이름·프사는 `assistant.identity`에 revision과 함께 보관한다. 프롬프트의 `CURRENT_ASSISTANT_IDENTITY`가 현재 정체성을 명시하며 과거 이름이 들어 있는 대화·기억은 역사로 남긴다. UI의 이름과 사진, 새 답장 알림도 현재 설정을 읽는다. 추론 도중 이름이 바뀌면 관찰된 기존 Work 결과를 보존하고 같은 작업의 모델로 후속 확인한다. 이미 실행된 클라우드 행동을 재실행하지 않도록 지시한다.

프사 원본은 SHA-256으로 고정된 일반 원본 파일이다. 화면에서는 기존 미디어 디코더로 크기를 제한하고 회전 정보를 적용한다. AI는 `app.identity.avatar`로 현재 사진을 실제 첨부 경로로 받을 수 있다. 설명이 없는 새 프사는 다음 사용자 요청에 여유 슬롯이 있을 때 함께 전달한다. 업로드 관찰 영수증·현재 revision·사진 해시가 일치할 때만 그 사진 설명을 저장한다. AI 프사를 사용자 발언으로 기록하지 않는다. 한 번 확인한 사진을 매번 다시 업로드하지 않는다.

## 백업 범위

전체 ZIP은 기존과 동일하게 **모든 SQLite 설정 행**과 원본·작업 파일을 보관한다. 사용자 지침, 목표, 영구 모델/추론/속도, 자율 주기, 기억 옵션, 사용량 목표, 도구 권한, 알림·다운로드·실행 한도, 비서 이름·프사·사진 설명이 함께 복원된다. 현재 화면의 임시 선택은 복원하지 않는다. 접수한 작업에 결합된 선택은 작업 기록의 일부로 보존한다.

Android 운영체제의 권한 승인·외부 폴더 접근 허용, WebView 로그인 세션은 이 설정 백업으로 다시 승인하거나 보장할 수 없다. 기존 백업 복원 정책에 따라 자율 실행은 복원 뒤 사용자가 다시 시작한다.

## 검증 범위

[집중 검증 기록](benchmarks/android-v041-focused.json)에 실제 실행한 클래스와 결과를 기록했다. 화면 이탈·꺼짐·회전, 전송 직후 종료, 여러 메시지, 기존 작업 후속 처리, 모델 선택과 작업의 동시 요청, stale 설정, 프로필 변경 도중 응답, 실제 첨부 경로의 관찰 영수증, 새 저장소로의 개인 설정·프사 원본 복원을 검사한다.

실제 Galaxy S24 Ultra와 실제 Work 모델 응답은 이번 검사에 포함하지 않았다. 장기 기억 검색·정정·삭제 알고리즘을 변경하지 않았으므로 이전의 전체 5년 시뮬레이션을 반복하지 않았다. 임시 선택 유지 검증은 앱의 작업 선택 보존에 대한 것이며 Android 강제 종료가 실행 중인 클라우드를 항상 복구한다는 보장은 아니다.
