# 재설치 후 기억과 삭제·제외 정책 보존 — 0.3.1

이전 0.3.0은 기억 ZIP과 내부 삭제·제외 정책을 분리해 앱을 제거하면 정책도 사라졌다. 0.3.1은 같은 공유 폴더에 기억 ZIP과 최신 정책을 보관하고, 재설치 후 폴더를 다시 연결해 정책을 먼저 합친 뒤 기억을 복원한다. 운영 DB는 빠른 내부 SQLite에 유지한다. 평소 검색·추론은 외부 폴더에 접근하지 않는다.

## 사용 순서

1. 파일 탭의 **보존 폴더 선택·다시 연결**에서 `Documents/호영` 같은 전용 공유 폴더를 선택한다. 앱 전용 `Android/data`·`Android/obb`는 거절한다.
2. 삭제·제외 기록은 변경 시 별도 IO 작업에서 자동 보존한다. **외부 보존 확인됨** 표시를 확인한다. 대기·권한 오류는 완료로 표시하지 않는다.
3. 전체 대화·기억·정정 이력·첨부는 **보존 폴더에 대화·기억·파일 백업 저장**으로 같은 위치에 저장한다. 전체 데이터의 자동 주기 백업은 제공하지 않으며 복구 범위는 마지막 ZIP까지다.
4. 재설치·데이터 초기화 뒤 같은 폴더를 먼저 다시 연결한다. Android의 영속 URI 권한도 제거 시 초기화되어 사용자의 재선택이 필요하다.
5. 원하는 ZIP을 복원한다. 연결한 폴더의 최신 정책과 로컬 정책을 먼저 합치므로 오래된 ZIP의 삭제된 원문·파생 기억이 AI 근거로 다시 사용되지 않는다. 물리 삭제의 완료·공유 파일·미추적 사본·대기 범위는 기존 삭제 영수증 기준을 그대로 따른다.

## 정책 형식과 순서

- 새 ZIP은 V3이며 체크섬 index에 `owner-policy/controls.json`도 넣는다. V1/V2는 계속 읽을 수 있지만 이식 정책이 없는 과거 백업이다.
- `OwnerPolicyBackup`은 기존 검증된 privacy snapshot과 `{type,id,hash}` 삭제 의도만 보관한다. 제공자 기록 삭제나 실제 바이트 정리 완료를 가정하지 않는다. 설치별 HMAC 키, 파일 삭제 경로, 큰 파생 파일 manifest는 내보내지 않는다.
- 삭제 식별 정보는 인증된 로컬 intent inventory에서 가져온다. 작은 정책을 보존하기 위해 큰 파일 manifest 전체를 매번 읽지 않는다. 재설치에서는 원본 hash·세대·실제 출처 관계를 다시 확인해 새 설치의 로컬 삭제 의도를 만든다. 누락 의도를 먼저 등록한 뒤 기존·새 삭제 의도를 단일 pass에서 재검사하여 같은 복원 작업에서 DB·파일 정리를 두 번 반복하지 않는다.
- 모든 입력은 schema·정수 ID·typed source hash·개수·byte bound·전체 JSON·checksum을 검증한다. 잘못된 기록은 빈 정책으로 대체하지 않는다.
- `SourcePrivacyLedger.mergeSnapshot`은 이미 있는 결정을 유지하고 빠진 제외만 한 번에 추가한다. 동일·오래된 부분집합은 fingerprint를 바꾸거나 운영 정책을 다시 쓰지 않는다.
- 완전한 ZIP의 SQL·원문·첨부·휴대폰 journal 검증 후, 원문 namespace를 바꾸기 전에 이식 정책을 내부의 독립 보존 영역에 먼저 합친다. 이후 DB 복원이 실패해도 제외 정책이 약해지지 않는다.
- 앱 startup과 실제 runtime 복원은 정책과 삭제 의도를 재검사한 뒤 UI·Work·수집기·색인을 준비한다. 없는 원문에 대해 빈 삭제 file manifest를 만들지 않는다. 나중에 옛 ZIP이 그 원문을 되살리면 실제 원문으로 삭제 대상을 다시 잡는다.
- 같은 ID의 다른 canonical hash는 별도 세대이므로 삭제하지 않는다. 기기 관찰의 동일 hash 재적재는 기존 전역 hash 제외를 유지한다.

## 외부 폴더 저장과 성능

`ExternalOwnerPolicyFolder`는 실제 Android DocumentsContract/SAF API를 사용한다. 정책은 고유한 임시 문서에 쓴 뒤 실제 read-back hash를 확인하고 rename으로 게시한다. 이전 완료 문서를 덮어쓰지 않으며 새 문서의 가시성과 내용까지 확인한 뒤 완료 상태를 저장한다. 두 개의 완료된 정책 snapshot을 남겨 저장량 증가를 제한한다. 정리 실패는 이전 사본을 더 남길 뿐 새 정책을 지우지 않는다. 불완전한 임시 문서는 정책으로 읽지 않으며, 손상된 완료 문서는 옛 정상 기록으로 조용히 대체하지 않는다.

보존 중 새 제어가 들어오면 요청 세대를 비교해 보존 대기를 유지한다. 기존 실행 중인 mirror가 새 요청의 pending 상태를 지울 수 없다. 초기 연결·제어 변경·실패 재시도·명시적 백업 때만 외부 IO를 한다. 연결이 없거나 보존 대기가 없으면 기존 1분 로컬 점검에서도 provider IO가 없다. 실패 시 최신 로컬 정책은 유지하며 자율 모드의 후속 로컬 점검에서 60초 이후 재시도한다. 자율 모드가 꺼져 있으면 재연결 또는 다음 앱 시작으로 다시 시도한다.

추가 모델 호출은 0개다. retrieval ranking, alias 처리, 원문 검색 예산, DB schema와 모델 입력 구조는 바꾸지 않았다. 정책 저장·read-back·명시적 대용량 ZIP에는 IO 비용이 있으므로 실제 폰의 지연이 정확히 0ms라고 주장하지 않는다. 주기적인 대용량 ZIP 작업을 새로 넣지 않는다.

## 확인 범위

새 25개 저장·보존 unit 시험은 실제 Robolectric native SQLite와 파일 IO로 최신 정책 + 옛 ZIP, 내부 namespace 초기화 후 복원, 정정 이력, 다른 세대 보존, 정책 변조·누락, V2 호환, 저장 중 실패, rename 실패, read-back 불일치, 완료 문서 손상, 세대 경합, 최대 두 개 snapshot, 상태 확인의 provider IO 0개와 삭제 DB 정리가 한 번만 실행됨을 검증한다. 추가 runtime 호출 경로 3개는 작업 중 정책 변경 거절, 최신 owner epoch 재조정, 제외 원문 보존·삭제 원문 정리와 추가 모델 전송 0개를 확인한다. 저장 제공자 인터페이스의 unit 시험은 파일 fixture이며 실제 Android 권한 부여를 가장하지 않는다.

추가 Android instrumentation은 TEST APK의 별도 UID document provider, 실제 persistable tree grant와 DocumentsContract IO·rename, 내부 대상 namespace 초기화 후 최신 정책 + 옛 ZIP, 완료 문서 손상 거절을 검증하도록 추가했다. 실제 OS 앱 제거·설치, 삼성 picker·S24 속도·외부 클라우드 제공자의 지원은 별도이며 이 시험으로 보장하지 않는다. 최종 실행 결과는 배포 검증 기록에 연결한다.

이 기능은 공유 폴더 자체 삭제·폰 초기화·보존 완료 전 앱 제거·잘못된 폴더 선택·다른 기기와 동시 쓰기를 해결했다고 주장하지 않는다. 마지막 ZIP 이후의 일반 대화는 아직 외부에 자동 복사되지 않는다. 이미 내보낸 옛 ZIP과 제공자 서버 사본 자체도 지우지 않는다.
