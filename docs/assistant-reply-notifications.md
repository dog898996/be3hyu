# 호영 답장 알림의 계약

`AssistantReplyNotifications`는 저장된 호영 메시지를 Android `NotificationManager`에 게시한다. 포그라운드 서비스의 실행 상태 알림과 별도인 `hoyoung_replies_v1` 채널을 사용한다. 완료된 답장, 필요한 선톡, 결과를 기다리는 답장, 한도 소진과 오류 안내가 대상이다. 내부 작업 진행, 주기 점검, 기억 검토, 아무 일이 없는 점검은 알림을 만들지 않는다. 호출자는 사용자에게 전달할 실제 메시지를 저장한 뒤 그 메시지와 단계만 넘긴다.

## 소스, 중복과 중단

알림마다 저장된 메시지 ID와 원문 레코드 해시를 확인한다. 사용자 메시지나 변경된 해시를 호영 답장으로 게시할 수 없다. `hoyoung_reply:<messageId>` 태그와 고정 ID를 사용하고, `replyNotification:<messageId>`에 게시 의도를 먼저 저장한다. 서로 다른 런타임 인스턴스도 같은 메시지를 고정 크기의 공유 잠금으로 직렬화한다. 저장된 상태를 조사하는 것은 해당 메시지의 한 행이며 대화 전체를 순회하지 않는다.

정상 호출의 `queued`는 로컬 작업자가 받아들였다는 의미다. Android `notify`가 반환한 뒤에만 `posted`를 기록한다. Android와 SQLite 사이에는 하나의 원자적 트랜잭션이 없으므로 중단 상태 `dispatching`에는 다음과 같이 대응한다.

- 동일한 ID·태그·해시의 실제 활성 알림이 있으면 게시된 상태로 복구한다. 다시 `notify`하지 않는다.
- 활성 알림이 없으면 `outcome_unknown`으로 보존하고 자동 재발송하지 않는다. 이미 사용자가 지운 알림인지, 실제 호출 전에 종료되었는지 구분할 근거가 없기 때문이다.
- 상태가 손상되었거나 알 수 없는 형식이면 원본 값을 남기고 `notification_state_corrupt_no_replay`를 보고한다. 손상을 새 메시지로 취급하지 않는다.

게시되거나 대화 화면에 표시되어 억제된 메시지는 앱을 다시 열어도 재알림하지 않는다. OS 권한이나 사용자의 설정이 막은 `not_allowed` 메시지는 동일 소스를 명시적으로 다시 요청할 때 현재 권한을 재검사한다. 설정 변경이 지난 메시지를 자동 재발송하지는 않는다. 백업 복원으로 같은 숫자 ID에 다른 레코드가 대응하면 현재 해시를 확인한 새 메시지로 취급한다.

활성 답장 알림은 최대 32개로 제한한다. 오래된 표시를 제거해도 원문이나 기억을 삭제하거나 읽음으로 처리하지 않는다. 포그라운드 서비스 알림에는 손대지 않는다. 개별 상태는 일반 작업 데이터로 저장되어 백업에 포함되며, 시작할 때 모든 과거 상태를 읽지 않는다.

## 화면, 설정과 개인정보

대화 화면의 실제 가시성은 `setConversationVisible`로 전달하며 이 호출은 DB를 읽지 않는다. 작업자는 게시 직전에도 가시성·권한·채널을 재확인한다. 앱 내부 `replyNotificationsEnabled` 설정, Android 13 이상의 `POST_NOTIFICATIONS`, 앱 전체 알림 허용, 채널 비활성화를 모두 존중한다. 사용자가 바꾼 채널을 생성자가 다시 활성화하지 않는다. `close`는 새 요청을 막고 소유한 작업자를 종료하며 호출 스레드에서 대기하지 않는다.

본문 미리보기는 400자, 펼친 본문은 1,200자로 제한하며 제어 문자와 UTF-16 경계를 처리한다. 잠금 화면에는 `VISIBILITY_PRIVATE`를 지정하고 공개 버전에 메시지 원문이 없는 일반 안내를 넣는다. 클릭은 변경할 수 없는 명시적 `PendingIntent`로 해당 대화·메시지 ID를 연다. 알림에서 직접 답장하는 기능은 아직 없다.

`markSeen`은 호출자가 해당 메시지를 실제 대화 화면에 표시했다고 확인할 때만 해당 알림을 취소하고 `readConfirmedByUi`를 저장한다. 화면에 표시된 사실이 사람이 읽고 이해했다는 증거는 아니다. 게시·복구·자동 취소는 읽음이나 업무 완료를 의미하지 않으며 `state()`도 게시를 읽음으로 보고하지 않는다.

알림에는 `assistant_reply`, 메시지 ID·해시·단계의 정확한 출처 정보를 넣는다. 알림 접근 수집기는 앱 자신의 알림을 비서가 생성한 표시 이벤트로 기록하고 외부 입력 트리거에서 제외한다. 다른 앱이 같은 추가 정보를 복사해도 호영 메시지 출처로 인정하지 않는다. 따라서 선톡 알림을 다시 읽고 또 선톡하는 순환을 만들지 않는다.

## 검증 범위

Robolectric 테스트는 실제 Android `NotificationManager` API와 SQLite를 통해 비공개 표시, 화면 억제, 한도·오류 안내, Android 35 권한 거부, 앱·채널 설정, 재시작 중복, 게시 도중 중단, 손상 상태, 동시 인스턴스, 원문 위조, 저장 실패, 최대 활성 수와 클릭 대상을 검증한다. 별도 휴대폰 수집기 테스트는 자기 알림의 출처 분류를 검증한다.

이 검증은 실제 Galaxy에서 알림이 표시되었다거나 사람이 읽었다는 실측 결과가 아니다. Android 게시 접수와 화면 표시·읽음을 구분하며, 잠금 화면·방해 금지·제조사 설정은 OS가 결정한다. 이 알림 기능만으로 앱 프로세스의 24시간 생존이나 클라우드 작업의 성공을 증명할 수는 없다.
