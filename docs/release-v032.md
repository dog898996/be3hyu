# 호영 0.3.2 사용량 최적화

[GitHub Release](https://github.com/dog898996/be3hyu/releases/tag/v0.3.2)에서 안정 서명 APK·전체 소스·검증 기록과 체크섬을 제공한다. 사용자 응답은 Fast, 무변화 정기 판단은 Light/Standard 후보, 기억 추출은 Medium 이상으로 요청한다. 실제 실행은 Medium/High로 넘긴다. 10%는 사용량 화면 전체 공유 한도의 일평균 절약 목표이며 강제 차단 한도가 아니다.

## 적용과 기억 보호

0.3.1과 같은 인증서의 versionCode6이므로 기존 release 설치 위에 업데이트한다. 기존 기억 DB·정정 이력·삭제 및 제외 정책·보존 폴더 연결·권한40개를 유지한다. debug나 다른 서명에서 전환하는 경우는 [설치 안내](../mobile/README.md)에 따른다.

전체 지침·사용자 설정과 기억 원문을 계속 전달한다. 반복 도구 명세는 해독 안내문을 포함한 원형 복원 검사를 통과한 경우에만 묶어 표현한다. 알 수 없는 구조는 원래 정의를 남기고, 잘못된 실행 형식·인자가 네이티브에서 거절되면 같은 작업의 기존 후속 턴에서 전체 명세로 돌아간다. 기억의 검색 개수·예산·원문·출처·현재 권한 검증·정정·삭제·검토 완료 기준은 줄이지 않는다. 추가 제목이 기억 공간을 잡아먹지 않도록 기존 프롬프트 크기 상한을 검사한다.

## 사용량 확인

설정의 절약 모드는 기본으로 켜져 있다. 사용자 요청에 Light를 먼저 호출하지 않고 선택한 Medium 이상/Fast로 보낸다. 새로운 폰 이벤트·진행 목표·불확실하거나 미검토된 기억은 정기 판단도 Medium 이상으로 처리한다. 한도 목표 초과 때문에 대화·5분 판단·기억 검토를 중단하지 않는다. 실제 서비스의 한도 소진은 별도로 처리한다.

Work 탭에서 계정의 실제 사용량 화면을 열고 **설정 → 열린 Work 사용량 화면 읽기**를 누른다. 수치·리셋 시각을 확인하지 못하면 관찰 완료로 표시하지 않는다. 같은 계정의 전체 공유 한도 변화와 관찰 범위를 기록하며, 다른 Work/Codex 작업과 표시 오차도 고려한다. 계정 구분 이름은 사용자 라벨이며 계정 신원을 독립 검증한 값이 아니다. 수동 입력은 공급자 확인과 구분한다. 실제 사용량을 측정하기 전에는 일평균10% 달성으로 표시하지 않는다.

## 검증

[로컬 검증](benchmarks/android-v032-optimization-local.json): Java893개 중877개 통과·선택형16개 제외·실패와 오류0개. Node259개 통과, Work DOM58개 포함. JavaScript는 해당 Node 검증 이후 변경되지 않았다. Debug·instrumentation·release APK와 debug/release lint 통과, 각 lint 오류0개·경고16개다. [소스 지문](benchmarks/android-v032-verified-source.json)은 코드·설정225개를 확인한다.

[365회 세션 모의시험](benchmarks/android-v032-longitudinal-memory.json)은 방해 기록30,660건과 정정·별칭·원문96개 조건을 모두 통과했다. [5년 기록 원문 회귀](benchmarks/android-v032-five-year-memory-regression.json)는 432/432개 조건, 최종144/144개 패킷과 이전 V7 패킷의 정확한 동일성을 확인했다. 삭제6건·옛 캐시12건 거절·옛 백업 복원12/12개도 통과했다. 손으로 작성한 기억·검토 ACK와 합성 기록을 사용하는 저장·검색 시험이며 새로운 실제 모델144개 답변의 정확도 시험은 아니다.

[최종 실제 API35 KVM CI](https://github.com/dog898996/be3hyu/actions/runs/38518027292)는 같은 코드에서 Java893개 중876개 통과·선택형17개 제외·실패0개, 실제 Android 기본18개와 종료·재시작·재부팅9개 복구 단계 플래그를 모두 통과했다. 실제 네이티브45개 명세 원형 복원과 기억/속도/사용량 목표 조건도 확인했다. [실제 Android 기록](benchmarks/android-v032-final-native.json)에 원본 로그 해시와 범위를 남긴다.

판단 fixture의 새 입력은 전체 Medium/Standard24,521에서 Light/Standard7,202 UTF-16자로 줄었다. 실행 명세59개는 16,610→11,526자로 약30.6% 줄면서 전체 정의를 복원했다. 이는 모델 입력 문자 비교이며 토큰·한도 차감·의미 정확도 비교가 아니다. [설계·모델·관측 조건](token-optimization.md)에 자세히 기록한다.

검증 코드 `36c2af8fbb7de2f912e8b068a6ae29f1f96b4495`, APK SHA256 `222ef280ee17aab64107e522ad7171e6db7977e27e1d4dd7005fe3940c0d4a3e`, 공개 서명 인증서 SHA256 `5b634dac5d4538f871ff0bfdbe1b31b2baa02dbe4390d11d7f6af235b2df1e3e`를 구분한다. 서명 개인키·실사용 DB·브라우저 쿠키는 공개 소스에 넣지 않는다.

실제 Galaxy S24 Ultra 지연·24시간 연속 운용, 실계정 Work UI·서버 적용 모델, Light/Medium 답변 동등성, 일평균10%는 아직 측정하지 않았다. Fast 선택은 즉답 보장이 아니다. 추가 유료 API·사설 VM·유료 CI를 사용하지 않았다.
