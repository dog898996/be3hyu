# Android phone capabilities

The mobile app targets Android 15 (API 35), with Android 8 (API 26) as its minimum. `PermissionCatalog` reports the device's actual grants at the time of reading. A default-enabled app tool setting does not grant an Android permission. The user must approve ordinary permission prompts and personally enable special accesses in Android Settings. The app cannot silently enable accessibility, notification access, all-files access, device administration, or other system permissions.

`PermissionCatalog(Context)` provides:

- `JSONArray snapshot()`: entries `{id,label,kind,runtimePermissions,granted,action,notes}`. `kind` is `runtime`, `restricted`, or `special`. `action` is `request_runtime`, `open_settings`, or `unsupported`.
- `String[] missingRuntimePermissions()`: missing, manifest-declared ordinary permissions suitable for a foreground permission request. Background location and installer/role-restricted SMS or call-log permissions are excluded.
- `void openSettings(Activity activity, String id)`: opens the corresponding Android screen without operating its controls. Unsupported screens fall back to the app-details screen.

The `location` entry is usable when approximate or precise location is granted. Contacts and calendar entries show both read and write grants together; their individual tools check only the required grant. On Android 14+, selected-image access is shown separately from full photo-library access. A granted permission remains subject to Android role restrictions, device policy, foreground requirements, and the user's later revocation.

| Access | Implementation and limits |
|---|---|
| Contacts and calendar | Bounded reads and individual contact/event creation through Android content providers. Write operations only occur for an explicit tool request. |
| Location | Recent last-known location only, with a caller-supplied age bound; no continuous tracking starts implicitly. Background location is a separate Settings step. |
| Camera and microphone | Grant state is visible. A flashlight tool uses camera permission; microphone recording and camera capture are not automatically started. |
| Phone and SMS | Dialer opening does not place a call. No SMS sender or direct-call tool is shipped. SMS and call-log access are installer/role restricted and are not included in the ordinary batch request. |
| Nearby devices and media | Grants for Bluetooth, Wi-Fi, photos, video, audio and selected images are reported where the OS supports them. Granting these does not itself implement scanning, network changes, or media uploads. |
| Notification display | Separate from reading other applications' notifications. Foreground-service notification requirements still apply. |
| Notification access | `HoyoungNotificationListener` keeps at most 250 posted/removal records in private SharedPreferences. Each record has package, key, title, text, event time, original posted time and removal reason. No network operation runs in the listener. `phone_notifications_read` returns only a requested bounded subset, with provenance and `sensitive:true`/`requestScoped:true`; the runtime may pass it to the active authenticated Work request when explicitly requested. Android may redact OTP/sensitive contents. |
| Accessibility | `HoyoungAccessibilityService` has an on-demand tree capped at 300 nodes and depth 16, latest-snapshot node IDs, exact-text clicks that reject ambiguity, navigation, and bounded gestures. Password nodes and editable text are omitted; input events are not retained. Android Settings, permission-controller and installer clicks/gestures require manual user operation. Gesture acceptance is not claimed as confirmed completion. |
| Usage access | Its actual grant is reported. It does not grant another app's private files or screen content. |
| All-files access | Functional shared-storage tools `phone_files_list`, `phone_files_read`, `phone_files_write` use this actual grant on Android 11+. Android 8–10 requires the relevant ordinary READ/WRITE storage grant and actual OS access; scoped-storage restrictions still apply. Tools accept only relative paths under the shared external root, reject traversal/symlinks and `Android/data`/`Android/obb`, and never recurse or delete. Listing caps at100 entries, UTF-8 reads at50000 characters and1MiB input, atomic UTF-8 writes at100000 characters. This is not root. The app's durable memory/files use private storage independently. |
| System settings | Brightness can be written after Write System Settings access. Secure/global settings are not claimed writable. Automatic brightness may override the written value. |
| Notification policy | Separately enabled Do Not Disturb policy access may be needed for ringtone/volume changes. |
| Overlays | Grant state and Settings link only; overlays do not grant screen capture or touch injection. |
| Battery exemption | Opens the system exemption list. This does not guarantee minute-by-minute execution, force-stop recovery, or unrestricted foreground-service time. |
| Optional exact alarms | Shows the actual `canScheduleExactAlarms` state. Not required for the basic worker, and not treated as a 24-hour AI scheduling guarantee. |
| Optional legacy device admin | Receiver declares only force-lock policy. No destructive admin tool is supplied. This is not device-owner or root access. |

`PhoneTools(Context).catalog()` returns22 `{name,description,inputSchema}` tool definitions. `execute(String name, JSONObject args)` always returns a JSON result: `ok`, `code`, `message`, and bounded tool-specific data. Unknown tools return `unsupported`; actual denials return `permission_missing` (with a `permissionId` when known). Clipboard reads require foreground state. App-launch and gesture results explicitly distinguish a request accepted by Android from confirmed completion. Every tool checks relevant Android permissions again when invoked; the runtime separately checks the app's editable per-tool allow settings before execution. Shared-file paths/content only enter the requesting Work result, not a background inventory upload.

On Android13 and later, a sideloaded APK can face **Restricted settings** when enabling accessibility or notification access. The OS may require the user to open Settings → Apps → 호영이 → the app-info overflow menu → **Allow restricted settings** (제한된 설정 허용), then return to the special-access screen. Exact menus depend on the manufacturer and installation method. This is an Android step that the app cannot approve for the user; it does not mean another app login or developer confirmation is required. See [Google's official restricted-settings instructions](https://support.google.com/android/answer/12623953?hl=en).

App inventory depends on Android package visibility. `QUERY_ALL_PACKAGES`, if declared for the personal assistant's installed-app management feature, remains subject to distribution-store policy review. A normal installation does not acquire root, system-signature permissions, device-owner status, another app's credentials, or perpetual operating-system execution rights.

Development validation must not read real users' contacts, notifications, location, clipboard, or private app data, and must not place calls, send messages or purchase anything. Shared-file Robolectric tests use synthetic files in the emulated test storage, exercising granted roundtrip, revocation, traversal/protected-directory/symlink rejection, type/size validation and malformed UTF-8. Compile/manifest checks can verify integration but cannot prove notification delivery, Samsung battery behavior, background wake frequency, or Settings grant screens. Those require explicit on-device verification after installation.
