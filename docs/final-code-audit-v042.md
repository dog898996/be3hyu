# 호영 0.4.2 최종 코드 검토

2026-10-14. 여섯 검토 에이전트가 분야별 코드를 검토하고, 통합 담당자가 실행·저장 경로를 교차 검토한 뒤 전체 변경분을 다시 직접 확인했다. 실제 오류를 고치고 관련 경계 조건만 로컬에서 재현했다. 유료 모델 호출, 실제 계정 로그인, 전체 5년 시뮬레이션·전체 에뮬레이터 검사는 수행하지 않았다.

## 검토 기준과 수정

| 분야 | 확인 기준 | 발견·수정 내용 |
|---|---|---|
| 장기기억 | 원문·현재 정정·기간·출처 세대가 맞아야 하며 제외 기록이 늘어도 조회 가능 | 약 1,000개 제외 조건에서 SQLite 표현식 깊이 오류가 발생하던 SQL을 집합 조회로 변경. 옛 기억의 canonical 출처 hash·role·관찰 시각을 복원해 사용자 원문이 AI 생성물로 잘못 분류되는 문제 수정 |
| 검색 유지보수 | 접근할 수 없는 최신 자료가 다른 기록의 처리를 영구히 막지 않음 | 의미 색인 작업이 제한된 배치를 순환하도록 변경. 권한이 없는 최신 기억 8개 때문에 오래된 정상 기억이 계속 밀리던 경로 해소 |
| 라우팅 | 화면 이탈·무관한 설정 변경이 진행 중 작업의 모델을 바꾸지 않음 | 최초 전송 시 root별 라우팅 설정 보관, 후속 처리에서 재사용. 해당 작업의 명시적인 채팅 설정 변경·승격은 반영. 영구 모델 설정만 바꿨다고 유효한 완료 응답을 폐기하지 않음 |
| 자율 판단 | 한도·전송 실패 후 복구하면 다음 정기 판단 가능 | 알려진 미전송·준비 중 중지·불명확한 결과 경로에서 주기 작업 점유와 임시 문맥·페이로드 해제. 실제 한도/불명확 상태의 자동 재전송 차단은 유지 |
| 작업 중 새 입력 | 새 지시 우선, 기존 결과 보존, 이미 끝난 행동 재실행 금지 | 새 사용자 입력으로 기존 작업이 조용히 종료되던 문제 수정. 이전 Work 출력에 출처를 연결하고 최신 입력을 대조하는 후속 요청으로 전달. 이전 폰 도구·기억 저장·사용자 답변은 먼저 실행하지 않음 |
| 토큰 효율 | 원문·기억 근거와 추론 강도를 깎지 않는 중복 제거 | 매번 달라지는 화면 세션 식별자를 큰 공통 프롬프트 뒤로 이동. 정기 판단의 높은 추론 설정은 실제 행동·후속 처리·기억 검토 및 최적화 비활성화 때도 유지 |
| 첨부·UI | 회전·앱 화면 교체·동시 초안 편집으로 파일이 사라지지 않음 | 첨부 가져오기를 Activity 콜백보다 먼저 영구 초안에 반영. 복원 세대 확인, 변경한 첨부 ID만 병합, 전송으로 소비한 첨부의 부활 방지. 종료된 화면 콜백·다른 탭 덮어쓰기 방지 |
| 개인 설정·프로필 | 이전 편집 화면이 최신 채팅 설정을 덮지 않음 | 실행 한도는 편집한 필드만 비교 저장. 계정 편집은 보았던 전체 레코드와 현재 값을 비교. 프로필이 저장 성공 후 표시되지 않는 MIME 불일치 거절 |
| 계정·복구 코드·백업 | 삭제한 계정의 과거 값이 재생성되지 않음, 사용한 일회용 코드 재사용 금지 | 이미 제외된 원문과 별개인 삭제 표식 생성, 외부 정책 폴더 동기화 예약, 계정 삭제와 ZIP 복사의 파일 장벽 공유. 복구 코드 상태 조회는 전체 사용 이력을 한 번만 검증해 집합 조회 |
| 폰 도구 | 사용자 제외와 실제 OS grant를 결과·보관 영수증에도 적용 | 알림 조회/재조회가 제외된 알림·부모 대화를 다시 노출하던 경로 수정. 최대 500개 후보의 공통 읽기 snapshot 사용. 앱 준비 후 활성 알림 snapshot을 한 번 예약. 연락처 0행 변경을 성공으로 보고하지 않음 |
| 브라우저·장시간 실행 | 중단된 응답의 파일·슬롯·실패 이력이 무한 누적되지 않음 | 문서/요청 종료 시 응답 캡처 스트림을 순서대로 닫고 부분 원문 보존. 이전 문서 콜백 무시, 실패 기록을 현재 요청으로 제한 |

통합 담당자의 마지막 재검토에서 추가로 발견한 문제도 수정했다. 완료된 목표의 출처와 과거 중지 설정이 매번 현재 문맥에 들어가며 1,024개를 넘으면 새 작업 준비가 실패했다. 이제 현재 활성 목표와 현재 작업의 정확한 키만 조회한다. 과거 blocked/quota/uncertain 요청은 전체 개수와 최근 32개·현재 root를 표시하고, 상세 범위를 명시한다. 과거 원문·작업 상태·출처는 그대로 보존하며 재실행 여부는 네이티브 실행기가 계속 확인한다.

## 지속가능성 판단

현재 화면은 제한된 메시지 페이지·썸네일을 사용한다. 정기 작업은 단일 점유로 예약하고 누락된 시간을 한꺼번에 재호출하지 않는다. 폰 이벤트·원문·기억은 canonical 저장소에 남고 검색 색인은 다시 만들 수 있다. 검색 후보·미디어 표시·색인 배치는 제한되며, 후보를 쓰기 전에 원문 hash·revision·권한·제외 여부를 확인한다. 백업 데이터는 행/파일 단위로 스트리밍한다. 이 구조와 이번 수정은 **장기간 쌓이는 데이터 때문에 반복 실행이 막히는 구체적 경로를 줄인다.**

영구 원문 보존은 저장량이 일정하다는 뜻이 아니다. 대화·파일·사진·폰 이벤트·실행 영수증은 사용량만큼 디스크를 차지한다. 검색과 상세 출처 검증·이력 통계·백업의 총 작업량도 데이터량과 무관한 상수가 아니다. 저장 공간 부족 시 원문을 몰래 지우거나 요약으로 대체하지 않는다.

현재 용량 경계는 전체 ZIP 최대 64 GiB(설정 1~64 GiB), ZIP 항목 최대 100,000개다. 항목 수는 모든 DB 행 수와 같지 않다. 삭제·제외 ledger와 복구 코드 ledger는 각각 16 MiB 및 100,000개 항목 제한이 있고 전체 문서 검증 비용이 남아 있다. 한계를 무제한으로 늘리거나 실제 폰에서 수년간 운용한 것으로 설명하지 않는다.

## 백업의 정확한 의미

- 전체 ZIP은 해당 시점의 대화·기억 revision·계정·개인 설정·프로필 원본·작업 파일을 복원한다. 더 오래된 ZIP으로 복원하면 그 이후 일반 대화와 사실 정정도 되돌아간다. 최신 사실 정정을 과거 ZIP 위에 자동 병합하는 기능은 아니다.
- 삭제·제외 정책과 일회용 복구 코드 사용 제어는 별도 portable union으로 유지한다. 외부 폴더가 연결·접근 가능하고 동기화가 완료됐는지 확인할 수 있다.
- 일반 대화·첨부의 전체 ZIP은 직접 저장한다. 작은 제어 정책의 자동 보존을 전체 원문 자동 백업으로 표현하지 않는다. 재설치 시 같은 보존 폴더를 먼저 연결한다.

## 검증과 해석

[이번 집중 검사 기록](benchmarks/android-v042-focused.json)은 실행 단계별 결과와 마지막 관련 재검사 결과를 함께 보존한다. 실패를 지우거나 같은 검사를 여러 번 성공한 것으로 중복 집계하지 않는다. 합성 출처·실제 native SQLite·Robolectric·모의 Work 전송으로 작은 경계 조건을 재현했다. 모델의 실제 답변 품질을 점수화한 시험은 아니다.

아래 항목은 이번 코드 검토만으로 보장하지 않는다.

- 실제 Galaxy S24 Ultra의 수년 운용, 배터리 소모, OS 종료 없는 24시간 연속성.
- 외부 Work 웹 UI·로그인 정책·요금제 한도 변경에도 영구 호환됨.
- 5년 전 모든 질문의 완전한 회상, 사용할수록 모든 질의의 정확도가 반드시 증가함.
- 하루 전체 사용 한도의 10% 이하. 이 목표의 실제 계정 소모율은 측정하지 않았다. 사용자 응답 Fast, 기본 정기 판단 Medium, 기억 검토 Medium 이상을 유지하며 UltraFast를 사용하지 않는다.

이번 검토에서 재현한 결함은 수정하고 관련 검사를 통과시킨다. 남은 항목은 실제 환경에서 측정해야 하는 범위와 명시된 저장/복원 계약이며, “오류가 전혀 없다”는 증명으로 바꾸지 않는다.
