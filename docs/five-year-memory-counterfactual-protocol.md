# Source counterfactual protocol

These checks were preregistered in [the evaluation plan](five-year-memory-evaluation-plan.md#accumulation-and-evidence-access). This file records an execution protocol, **not a passed result**. The [actual V5 native intervention run](five-year-memory-counterfactual-v5-results.md) now retains three changed/control packets; independent reader answers and semantic review remain required.

Use separately tagged copies of a completed canonical native snapshot. Keep the source manifest, query, date, context budget, reader settings and follow-up allowance fixed. Do not change the frozen matrix, expected answers, original run database or primary accuracy denominator.

After reader QA, select a factual question and a short, actually delivered/cited raw message. Record its native type/ID, original record hash, exact original text and quoted span. Select an unrelated message from the same native corpus by actual source inspection. Neither selection supplies an expected answer to a reader. Prefer the raw arm for the first check: a changed original invalidates existing writer references, and manually rewriting a derived note would obscure which component caused the answer change.

1. The unchanged control is the actual final packet and reader answer.
2. In the **relevant-source copy**, replace one answer-bearing literal span with a fresh synthetic value, preserving the message role and dates. Update only that source in the disposable native Store copy, using the production record-hash function and existing FTS maintenance. Check canonical row/hash and exact original delivery. The original source's old hash must not remain a valid reference to its changed bytes.
3. In the **unrelated-source copy**, change only the selected unrelated source with an equally explicit synthetic replacement. Keep the question and relevant sources unchanged.
4. Run the same frozen production search/context path for each copy. Retain native query arguments, emitted context, dependencies, diagnostics, scope controls, changed-source receipt and copied snapshot hashes. If either context blocks or fails to expose necessary evidence, report that outcome rather than injecting the missing source manually.
5. Give the independent reader only opaque questions, the actual emitted evidence and the same bounded native source tools. Do not supply `expected`, category labels, scenario names, a suggested answer, or the designation “relevant/unrelated.” Keep the mutation receipt and these designations scorer-only until the answers are frozen.
6. Review semantic content and provenance: the answer must change consistently with the relevant source edit, and remain factually stable after the unrelated edit. Identical wording is unnecessary; unsupported extra claims are failures. A stale value accompanied by the old source hash, a confident unchanged answer to changed evidence, or a changed factual answer after unrelated noise is a failure.

The mutator needs a native source ID/hash, old/replacement span and actual query; it needs **no answer rubric or generated expected answer**. Selecting a source that a reader really cited avoids an oracle-assisted retrieval shortcut. Mechanical context differences establish source sensitivity only; they do not establish the required model-answer sensitivity.

Record the changed exact spans and fresh synthetic values, source hashes before/after, unchanged source counts, failed hash references, reader requests/row budgets, full original/changed answers and independent judgments. These are paired interventions, not fresh independent accuracy samples. An unavailable fixture, unsupported mutation path, incomplete follow-up or unexecuted reader stays not measured. Local modifications do not establish real-phone behavior, deployed Work calls or actual years of use.
