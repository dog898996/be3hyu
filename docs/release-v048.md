# 호영 0.4.8 — 한국어 Work 선택 확인과 대화 화면 비우기

## 연결 오류

사용자가 보낸 0.4.7의 영상과 현재 문서 진단에서 선택창·슬라이더는 각각 하나씩 발견됐지만 모델은 미확인, Fast 제어는 0개였다. 실제 메뉴에는 `모델 선택 | GPT-6.1 Sol Medium`, `Fast 모드 활성화`가 있었고 후자는 `menuitemcheckbox`, `aria-checked=false`였다. 영상에서도 팝업을 연 뒤 자동 선택이 중단되는 것을 확인했다. 전체 개인 진단과 영상은 저장소에 복사하지 않았다.

- `Fast 모드 활성화`·`Fast 모드 비활성화`처럼 영어와 한국어가 섞인 표시를 인식한다. 체크박스에서는 활성화라는 문구가 계속 남더라도 실제 `aria-checked`·`aria-pressed` 상태를 먼저 읽는다. 켜진 Fast를 꺼진 것으로 오판해 다시 누르지 않는다.
- 모델 헤더가 여러 텍스트 요소로 나뉠 때 `GPT-6.1`이라는 버전 조각을 별도 모델로 해석해 `GPT-6.1 Sol`과 충돌시키는 경로를 수정했다.
- 전용 데이터 속성이 없는 현재 모델 헤더는 연결된 팝업 안의 명시적인 `모델 선택` 제어로 찾는다. 두 헤더 형태 모두 재현 검사에 포함한다.
- 준비된 모델·강도·속도의 실제 관찰을 마친 뒤 선택창을 닫고 기존 전송 경로를 진행한다. 기본 Fast와 사용자의 Fast 끄기, 진행 중 작업의 고정 모델 설정을 유지한다.

## 화면 비우기

앱의 대화 화면 오른쪽 위 **⋯ → 대화방 비우기**를 누르면 그 시점까지의 메시지를 화면에서 숨긴다. **⋯ → 비운 대화 다시 보기**로 다시 표시할 수 있다. 별도의 삭제 확인이나 모델 호출은 필요하지 않다.

- 메시지·원문 파일·장기기억·수정 이력·검색 색인·첨부·반응·대기 작업을 지우지 않는다. 작성 중 초안과 진행 중 AI 작업도 유지한다.
- 새로 도착한 메시지는 표시한다. 숨긴 메시지를 대상으로 새 이모지 반응이 오면 독립된 반응 메시지로 표시하며, 이전 대화를 다시 보이면 기존 메시지의 반응으로 합쳐 표시한다.
- 페이지를 넘겨도 숨긴 과거 메시지가 섞여 나오지 않는다. 오래된 알림을 누르면 해당 원문만 열며 전체 화면의 비우기 상태를 해제하지 않는다.
- 화면 표시 경계만 일반 설정에 저장한다. 앱 재실행과 정상 백업·복원에 따라 유지된다. 다른 데이터베이스에서 가져온 잘못된 표시 경계가 새 대화를 숨기지 않도록 원문 식별자와 해시를 함께 확인한다.
- 메시지 및 기억 검색은 기존 전체 기록 경로를 사용한다. 화면 비우기를 기억 삭제·기억 제외로 해석하거나 모델에게 잊으라고 전달하지 않는다.

## 검사와 설치

변경 전 한국어 선택창 재현 두 검사가 실패하는 것을 확인했다. 변경 후에는 해당 구조에서 자동 연결·Fast 켜기/끄기·팝업 닫기·전송 접수·답변 수집을 확인했다. 이는 제공받은 진단에 맞춘 브라우저 재현이며 실제 계정의 모델 응답을 호출한 결과는 아니다.

원문·검색·기억·작업 큐가 비우기 전후 동일한지, 재실행과 백업·복원 후에도 화면 설정만 유지되는지, 새 메시지와 이전 페이지의 경계가 맞는지 확인한다. 실제 네이티브 메뉴에서 초안과 진행 중 작업을 유지하면서 비우기·새 반응 표시·다시 보기가 작동하는지도 검사한다. 전체 장기기억 시뮬레이션과 유료 모델 호출은 수행하지 않는다.

브라우저 연결 검사 **86/86**, 변경과 관련된 네이티브·저장소 검사 **17/17**를 통과했다. 연결 검사는 유료 모델 없이 재현 문서에서 수행했고, 저장소·화면 검사는 실제 SQLite와 네이티브 위젯을 사용했다. 서명 릴리스 빌드·필수 lint·APK 검사·패키징된 연결 파일 6개의 원본 일치 확인도 통과했다.

기존 앱 위에 업데이트하고 **Work → 연결**을 누른다. 실제 Galaxy에서의 최종 연결 성공은 아직 확인하지 못했으며, 로컬 재현 검사와 구분한다.
