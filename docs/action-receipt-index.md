# 실행 영수증의 장기 기록과 미확인 인덱스

행동을 실행하기 전에 `actionReceipt:<rootRequestId>:<actionId>`에 의도를 기록한다. 기록이 실패하면 외부 행동을 시작할 수 없다. 같은 행동 ID의 영수증은 결과 재사용, ID 충돌 확인, 접수 결과가 불확실한 행동의 자동 재실행 방지에 쓰인다. 1~2년 동안 쌓인 완료 영수증 전체를 시작할 때 JSON 배열로 읽지 않는다.

`ActionReceiptJournal.put()`은 영수증과 `pendingReceipt:` 인덱스를 같은 트랜잭션에서 저장한다. `completed`와 `abandoned`는 미확인 인덱스에서 제거하고 원 영수증은 유지한다. 일반 UUID 요청 ID의 인덱스 키는 `pendingReceipt:<영수증 키>`다. 옛 최대 길이 512문자 키는 해시 인덱스를 사용하며 실제 영수증 키를 값에 보존한다.

## 목표 보고의 네이티브 범위 확인

`completionSummary(rootId, mutatingTool, confirmedNativeReceipt)`는 실제 저장된 해당 원 요청의 영수증 키만 페이지로 읽는다. 매번 원 영수증 하나를 읽어 성공·실패·미완료와 변경 확인을 계산한다. 도구가 변경을 하는지와 실제 결과가 확인되었는지는 신뢰하는 런타임의 분류기만 전달하며 모델 JSON을 그대로 검사 결과로 받지 않는다. 실패한 읽기는 진단으로 남길 수 있지만, 실패한 변경·완료 미확인 변경·미완료·손상·분류 오류가 있으면 `ready:false`다. 같은 이름의 변경이 나중에 성공했다고 과거 실패를 자동 해결하지 않는다.

`snapshotHash`는 정렬된 실제 영수증 키와 원문 해시를 묶은 SHA-256이다. 목표 보관 트랜잭션에서 다시 계산하여 영수증이 바뀌었으면 이전 요약을 쓰지 않는다. 다른 원 요청과 접두어가 비슷한 원 요청의 영수증은 포함하지 않는다. 이 요약은 `proofScope:native_receipts_only`, `overallOutcomeVerified:false`이며 클라우드 작업이나 목표의 모든 요구 조건을 증명하지 않는다. 완료 보고를 운영상 보관하는 원장의 판단에만 사용한다.

## 첫 마이그레이션과 재시작

`ensureIndex()`는 백그라운드에서 실행한다. 영수증 키 128개씩만 읽으며 각 원 영수증을 하나씩 확인해 미확인 인덱스와 체크포인트를 저장한다. 한 번에 모든 원문이나 JSON 객체를 보유하지 않는다. 각 영수증의 트랜잭션 사이에서 저장소 잠금을 풀어 긴 마이그레이션이 전체 저장소를 계속 점유하지 않는다. 중간에 종료되면 저장한 키부터 다시 시작한다. 손상·빈 문자열·알 수 없는 상태는 미확인으로 남는다.

마이그레이션이 끝나야 `receiptIndexVersion=1`을 기록한다. 준비 중에는 `hasUnresolved()`가 차단 상태를 반환하므로 런타임은 새 외부 행동을 보내면 안 된다. 다음 시작에는 키 인덱스로 세는 영수증 개수와 `indexedReceiptCount`를 비교한다. 일치하면 원문을 다시 읽지 않는다. 준비된 상태에서 미확인 여부는 미확인 키 범위의 `SELECT 1 ... LIMIT 1`로 확인한다.

정상 앱 경로의 모든 영수증 변경은 저널을 사용해야 한다. 저널 밖에서 기존 영수증의 상태만 덮어쓰면 개수 비교만으로 감지되지 않는다. 백업 복원은 `ensureIndex(true)`로 재구축한다. 직접 수정·복구 도구도 같은 절차를 적용해야 한다. 이 제한을 숨기지 않는다.

## 사용자 확인과 원문 보존

`resolveFor(rootRequestId,abandoned)`는 사용자가 해당 원 요청의 결과를 확인하거나 추적에서 제외하겠다고 명시한 경우에만 호출한다. 한 원 요청의 키 범위만 읽으며, 완료 영수증의 큰 본문은 읽지 않는다. 실제 미확인 영수증만 갱신한다.

종료 전에 이전 영수증을 변경 없이 별도 내부 원문에 보존한다. 종료 기록에는 그 원문 ID, 해시, 행동 식별 지문, 가능한 이름·시각을 남긴다. 이전 실패·부분 실행 결과나 손상된 원본을 조용히 지우지 않는다. 사용자 확인은 외부 서비스 결과의 독립적 검증이 아니므로 `providerOutcomeVerified:false`, `replayed:false`를 명시한다. 종료는 행동을 다시 실행하지 않는다.

검증은 5,000개의 과거 완료 영수증과 미확인 한 개, 준비 상태와 재시작, 의도·인덱스 저장 실패의 원자적 롤백, 손상 기록, 옛 직접 기록의 개수 변화, 명시적 재구축, 원 요청별 종료, 이전 결과 원문 보존, 최대 길이 키, 백업 복원을 다룬다. 과거 5,000개 중 큰 본문은 32개이며, 백만 개의 최대 크기 영수증을 실제로 시험했다고 주장하지 않는다.
